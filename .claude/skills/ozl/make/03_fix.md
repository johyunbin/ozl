# 03 고치기 (작성자용)

너는 OZL 이슈 기록의 작성자다. 문장 대조 검토자(작성자와 다른 Claude 모델)가 지적을 냈다. `principles.md` 를 다시 읽고 시작한다. 고침 회차면 고칠 목록 파일의 원칙과 "그대로 두는 것"도 지킨다.

받는 것: 이슈 번호, 맹검 판정이 초안과 달랐던 주장, 지적 목록, 작업 폴더, 있으면 고칠 목록 파일.

## 순서

1. **지적마다 원문 사본을 직접 다시 열어 확인한다**(`<자료 루트>/issues/<번호>/captures/<근거 번호>/text.txt`). 사소한 지적도 고친다.
2. 지적이 틀렸다고 판단하면 고치지 않고, 원문의 대목을 근거로 대어 반박을 적는다.
3. 고친다. 이슈 기록과 근거 기록은 파이썬으로 읽어 고쳐 저장하고(`01_draft.md` 의 "기록 쓰는 법"), 저장한 뒤 다시 읽어 문장이 온전한지 본다. 새 공식 문서가 필요하면 `01_draft.md` 4단계대로 받는다. 대목(`observed`)을 바꾸거나 새 근거를 더하면 그 근거의 재대조 칸은 비워 두고 보고에 적는다(다음 문장 대조가 채운다).
4. **길이 상한 때문에 요건이나 단서를 빼지 않는다.** 상한에 걸리면 다른 낱말을 줄이거나 문장을 나눈다(`principles.md` 17).
5. **판정이 바뀌면 따라 바꿀 것**: 흐름, 지금까지 3줄과 `so_far_refs`, 제목과 제목 후보와 `basis_claims`, 무엇이 새로운가, 숫자 표시(`numbers`), `basis_facts`, `scope`, '확인 못 함'이면 사유와 `would_decide`.
6. `PY -m ozl.issues check <번호> --public` 을 돌려 오류와 경고가 0건인지 본다. 검사기를 통과시키려고 내용을 사실과 다르게 바꾸지 않는다.
7. `PY -m ozl.issues export --preview --out <작업 폴더>/preview` 를 다시 돌린다.

## 하지 않는 것

- 재대조 칸을 채우지 않는다. 다른 프로세스나 에이전트를 띄우지 않는다.
- 주장 목록을 늘리지 않는다. 게시 가부(`publish.state`)를 검토 진행 때문에 바꾸지 않는다.
- 승인, 내림, 공개용 내보내기를 부르지 않는다. 외부 모델을 부르지 않는다.

## 돌려줄 것 (600자 안팎)

지적마다 고침 또는 반박(근거 한 줄), 바뀐 판정, `check` 결과의 마지막 줄 그대로.
