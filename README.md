# OZL — 오늘의 즐길거리

경제·국제·사회 뉴스에서 방송 한 꼭지로 다룰 만한 소재를 골라 카드로 적고, 통과시킨 소재를 생방송용 슬라이드로 만드는 개인 작업 기록입니다. 슬라이드의 숫자마다 그 숫자가 적힌 공식 원문의 대목을 검증 기록으로 남기고, 덱의 출처 부록에는 기록 번호와 원문 위치·링크를 붙였습니다.

혼자 운영합니다. 제가 하는 일은 후보로 올라온 소재에 통과나 폐기를 표시하는 일과, 만든 결과물의 공개를 승인하는 일입니다. 기사 수집, 카드와 검증 기록 쓰기, 원문 대조, 슬라이드 만들기는 프로그램과 언어 모델 에이전트가 합니다. 숫자를 원문과 눈으로 대조하는 일은 2026년 11월 10일 첫 회차까지 제가 했고, 지금은 하지 않습니다.

슈카월드 생방송 자료의 구성과 형식을 기준으로 삼았습니다. 채널이나 제작사와는 관계없는 개인 작업입니다.

사이트: <https://johyunbin.github.io/ozl/>

## 먼저 볼 것

[2026년 11월 10일 아침 회차](https://johyunbin.github.io/ozl/daily/2026-11-10_am/)의 1번 카드입니다.

그날 밤 미국 10월 소비자물가가 발표될 예정이었습니다. 기사 제목에 늘 나오는 "1년 전보다 몇 % 올랐다"는 숫자가 이번 공식 발표에는 없다는 점을 소재로 잡았습니다. 2025년 가을 예산 공백 때 10월 조사를 하지 못해서, 대부분의 지수에 비교할 작년 값이 없기 때문입니다.

- 카드: [오늘 밤 미국 물가 발표에는 '1년 전보다 몇 % 올랐다'가 없습니다](https://johyunbin.github.io/ozl/daily/2026-11-10_am/#am-01)
- 검증 기록: [`claims/2026-11-10/`](claims/2026-11-10/) 의 `2026-11-10-am-01-c1` 부터 `c11` 까지. 주장 11건마다 원문 주소, 원문에 적힌 값, 기준 시점, 반대로 볼 여지를 적었습니다. 이 회차는 제가 미국 노동통계국의 문답과 보도자료, 연준의 금리 변경표를 열어 기록마다 원문과 눈으로 대조했습니다.
- 초안을 쓴 쪽과 다른 에이전트가 원문을 다시 열어 보았고, 11건 가운데 1건은 문장이 원문보다 넓게 쓰여 있어서 범위를 좁혔습니다.

슬라이드는 아직 공개한 것이 없습니다. 2026년 11월 13일에 통과시킨 소재 한 편을 아래의 완성 절차로 끝까지 만들었고, 비공개로 두었습니다. 공개는 제가 승인한 뒤에 합니다.

## 일이 도는 순서

1. 언론사, 통신사, 기관 발표 피드를 읽고 같은 사건을 다룬 기사를 묶습니다. 국내 정치 공방이나 사건 피해자처럼 다루지 않기로 한 소재는 이 단계에서 뺍니다. 예약 실행은 2026년 11월 13일부터 멈춰 두었고, 지금은 필요할 때 불러서 돌립니다.
2. 묶음에서 후보를 한 번에 0~3장 고릅니다. 새로 달라진 사실(새 수치, 결정, 충돌, 예상과 다른 결과)이 있어야 후보가 되고, 화제가 큰 것을 위에 둡니다. 최근 슈카월드 방송과 같은 사건이면 뺍니다. 올릴 만한 것이 없으면 그날은 후보를 내지 않습니다.
3. 저는 후보를 읽고 통과나 폐기를 표시합니다. 통과 뒤의 단계는 저에게 확인을 묻지 않습니다.
4. 통과한 소재는 슬라이드에 쓸 주장을 전부 검증 기록으로 만듭니다. 프로그램이 공식 원문을 받아 사본으로 저장하고, 기록에 옮긴 원문 표기가 사본에 그대로 있는지 대조합니다. 기록을 쓴 쪽과 다른 에이전트가 같은 자리를 따로 찾습니다.
5. 슬라이드는 판마다 세 가지 검토를 거칩니다. 다른 에이전트가 문장을 인용 기록과 원문에 대조하고, 다른 회사의 모델이 해석이 근거를 넘지 않는지 보고, 또 다른 에이전트와 그 다른 회사 모델이 방송 자료로서의 구성을 평가합니다(쪽 그림의 화면 점검은 에이전트가 합니다).
6. 완성본(슬라이드, PDF, 러닝시트, 검증 요약)은 비공개 폴더에 둡니다. 제가 승인한 것만 사이트에 올립니다.

사이트에는 공개한 적이 있는 회차의 쪽만 있습니다. 그 쪽에서 승인하지 않은 카드는 번호와 검증 배지만 보입니다(반려한 카드는 빠집니다).

자세한 설명과 첫 회차에서 실제로 있었던 일은 [작업 방식](https://johyunbin.github.io/ozl/how-it-works/)에 있습니다.

## 자동으로 하는 일과 직접 하는 일

| 자동(프로그램과 언어 모델) | 직접 |
|---|---|
| 피드 읽기, 같은 사건 묶기, 다루지 않을 소재 거르기, 후보 고르기 | 후보에 통과나 폐기 표시 |
| 카드와 검증 기록 쓰기, 원문 사본 받기와 문구 대조 | 공개 승인과 철회 |
| 다른 에이전트의 독립 재대조, 문장 대조, 구성과 화면 평가 | |
| 다른 회사 모델의 해석 점검 | |
| 슬라이드, 러닝시트, 보고서 만들기, 승인한 것을 사이트에 올리기 | |

카드와 기록 쓰기, 재대조, 문장 대조, 구성 평가에는 언어 모델을 씁니다. 주로 Claude 이고, 해석이 지나치지 않은지는 Gemini 나 ChatGPT 에 읽히고, 같은 모델에 구성 평가도 함께 묻습니다. 모델이 "맞다"고 적은 말은 근거로 치지 않습니다. 근거는 프로그램이 저장한 원문 사본에서 찾은 문구와, 기록을 쓴 쪽과 다른 에이전트가 같은 자리를 따로 찾은 재대조와, 원문 링크입니다. 사람이 대조하지 않고 프로그램 검사를 통과한 기록은 `확인`이 아니라 「원문 일치」로 표시합니다. 사람이 대조한 기록에는 검증 기록 파일의 `human_verified_by` 와 `human_verified_at` 에 누가 언제 대조했는지 남습니다.

## 숫자를 확인하는 방법

출처를 다섯 등급으로 나눕니다.

| 등급 | 무엇 | 쓰는 법 |
|---|---|---|
| T1 | 공식 통계, 법정 공시, 법령과 판결문, 기관 보도자료 원문 | 단독으로 쓴다. 단위, 기준 시점, 잠정치 여부를 확인한다 |
| T2 | 국제기구, 국책연구기관, 동료 심사를 거친 연구 | 단독으로 쓴다. 조사 방법을 함께 적는다 |
| T3 | 주요 언론의 사실 보도 | 두 곳 이상에서 확인하거나 T1·T2 원문까지 거슬러 올라간다. 같은 통신 기사를 받아쓴 것은 한 곳으로 센다. 슬라이드에서는 숫자의 근거로 쓰지 않는다 |
| T4 | 전문가 의견, 증권사 리포트, 심사 전 논문 | 주장이나 추정이라고 밝히고 반대 의견을 함께 적는다 |
| T5 | 커뮤니티, SNS, 출처 없는 글 | 인용하지 않는다. 소재를 찾는 단서로만 쓴다(커뮤니티 반응 자체가 주제일 때만 가려서 싣는다) |

검증 기록에는 등급이 붙습니다.

- `확인`은 사람이 원문과 눈으로 대조한 기록입니다. 적힌 숫자가 원문과 같고, 단위와 기준 시점과 비교 대상을 점검했습니다. 2026년 11월 10일 첫 회차의 기록이 여기에 듭니다.
- 「원문 일치」는 사람의 대조 없이 통과한 기록입니다. 프로그램이 공식 원문(T1·T2)을 받아 사본으로 저장했고, 기록에 옮긴 원문 표기가 사본에 그대로 있으며, 기록을 쓴 쪽과 다른 에이전트가 사본에서 같은 자리를 따로 찾았습니다. 기준 시점은 두 쪽이 적은 값이 맞아야 하고, 단위는 두 쪽의 판단(수량이 있는가)이 어긋나지 않아야 하며, 확정·잠정은 쓴 쪽이 적어 둔 기록에서만 견줍니다.

카드의 배지는 기록 가운데 가장 약한 것을 따릅니다. 기록이 전부 사람 대조면 `확인`, 프로그램 대조가 섞이면 「원문 일치」입니다. `추정`은 공식 발표 전의 복수 보도, `단독`은 한 곳만 보도한 내용, `루머`는 확인되지 않은 이야기이고, 등급을 받기 전에는 `검증 대기`입니다. 공개할 수 있는 것은 `확인`, 「원문 일치」, `추정`인 카드이고, 그 가운데 제가 승인한 것만 올립니다.

이 방식의 한계도 적어 둡니다.

- 첫 회차 뒤의 기록은 사람이 원문과 대조하지 않았습니다.
- 프로그램은 문구가 원문 사본에 있다는 것까지 확인합니다. 그 문구를 옳게 읽었는지는 에이전트와 다른 회사 모델의 점검에 달려 있고, 사람이 본 것과 같지 않습니다. 자동 점검을 통과했다고 정확하다는 보증은 아닙니다.
- 보도 기사는 숫자의 근거가 되지 않습니다. 「원문 일치」는 T1·T2 원문에만 붙고, 슬라이드는 기사를 숫자 없이 기사로만 인용합니다.
- 어느 등급이든 카드가 그 숫자로 펼치는 이야기 전체가 옳다는 보증은 아닙니다. 그래서 기록마다 가장 강한 반론과 남는 불확실성을 따로 적습니다.

발행한 뒤에 틀린 것을 찾으면 지우지 않고 [정정 기록](https://johyunbin.github.io/ozl/corrections/)에 남깁니다. 규칙 전문은 [검증 방법](https://johyunbin.github.io/ozl/methodology/)에 있습니다.

## 이슈 기록

화제가 된 이슈 하나를 골라, 떠도는 주장마다 판정과 근거를 붙인 기록을 만듭니다. 기록 한 건에서 웹의 이슈 화면, 옆으로 넘겨 보는 카드, 날짜별 흐름이 나옵니다. 방송 소재 카드와는 따로 돕니다.

판정은 넷입니다. `확인`, `일부 맞음`, `사실과 다름`, `확인 못 함`. '확인 못 함'에는 사유와, 무엇이 나오면 판정할 수 있는지를 함께 적습니다. 보도만으로는 '확인'을 붙이지 않습니다. 초안은 언어 모델이 쓰고, 다른 Claude 모델의 문장 대조와 다른 회사 모델의 해석 점검을 거칩니다. 저는 만들 이슈를 고르고 게시를 승인하며, 원문을 눈으로 대조하지는 않습니다.

지금은 제 맥과 사설망에서만 여는 미리보기까지 만들었고, 공개 게시한 이슈는 아직 없습니다. 판정 기준, 검토의 짜임, 게시 가부, 판과 정정, 수집 원칙은 [이슈 기록](https://johyunbin.github.io/ozl/issue-brief/)에 있습니다.
