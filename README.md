# OZL — 오늘의 즐길거리

경제·국제·사회 뉴스에서 방송 한 꼭지로 다룰 만한 소재를 하루 두 번 골라 카드로 적는 개인 작업 기록입니다. 카드에 쓴 숫자는 기관 원문을 직접 열어 맞춰 본 것만 공개하고, 고른 소재는 생방송용 슬라이드로 만듭니다.

혼자 운영합니다. 기사 수집과 카드 초안은 자동으로 돌리고, 어떤 소재를 쓸지 정하는 일, 숫자를 원문과 대조하는 일, 공개를 승인하는 일은 직접 합니다.

슈카월드 생방송 자료의 구성과 형식을 기준으로 삼았습니다. 채널이나 제작사와는 관계없는 개인 작업입니다.

사이트: <https://johyunbin.github.io/ozl/>

## 먼저 볼 것

[2026년 11월 10일 아침 회차](https://johyunbin.github.io/ozl/daily/2026-11-10_am/)의 1번 카드입니다.

그날 밤 미국 10월 소비자물가가 발표될 예정이었습니다. 기사 제목에 늘 나오는 "1년 전보다 몇 % 올랐다"는 숫자가 이번 공식 발표에는 없다는 점을 소재로 잡았습니다. 2025년 가을 예산 공백 때 10월 조사를 하지 못해서, 대부분의 지수에 비교할 작년 값이 없기 때문입니다.

- 카드: [오늘 밤 미국 물가 발표에는 '1년 전보다 몇 % 올랐다'가 없습니다](https://johyunbin.github.io/ozl/daily/2026-11-10_am/#am-01)
- 검증 기록: [`claims/2026-11-10/`](claims/2026-11-10/) 의 `2026-11-10-am-01-c1` 부터 `c11` 까지. 주장 11건마다 원문 주소, 원문에 적힌 값, 기준 시점, 반대로 볼 여지를 적었습니다. 미국 노동통계국의 문답과 보도자료, 연준의 금리 변경표를 직접 열어 대조했습니다.
- 초안을 쓴 쪽과 다른 에이전트가 원문을 다시 열어 보았고, 11건 가운데 1건은 문장이 원문보다 넓게 쓰여 있어서 범위를 좁혔습니다.

슬라이드는 아직 올린 것이 없습니다. 고른 소재로 만드는 중이고, 완성되면 이 자리에 둡니다.

## 하루가 도는 순서

1. 아침 7시 30분과 밤 9시에 예약 작업이 언론사, 통신사, 기관 발표 피드를 읽고 같은 사건을 다룬 기사를 묶습니다. 국내 정치 공방이나 사건 피해자처럼 다루지 않기로 한 소재는 이 단계에서 뺍니다.
2. 묶음에서 다섯에서 여덟 개를 골라 카드를 씁니다. 카드에는 왜 오늘 다룰 만한지, 핵심 숫자와 출처, 슈카월드가 전에 다룬 적이 있는지, 예상 구성, 반대로 볼 여지를 적습니다.
3. 그날 카드 가운데 위 세 장은 핵심 숫자를 원문에서 직접 확인하고 기록을 남깁니다. 초안을 쓴 쪽과 다른 에이전트가 원문을 한 번 더 엽니다. 나머지 카드는 출처 링크만 달아 둡니다.
4. 카드를 읽고 쓸 것을 고릅니다. 고른 카드는 적힌 주장을 전부 확인 대상에 넣고, 검증 시트를 보면서 원문과 눈으로 맞춥니다.
5. 맞춰 본 카드만 공개를 승인합니다. 승인하지 않은 카드는 사이트에 번호와 분야만 보입니다.
6. 고른 카드로 슬라이드를 만듭니다. 초안을 자동으로 뽑는 도구는 만드는 중이고, 지금은 대부분 손으로 합니다.

자세한 설명과 첫 회차에서 실제로 있었던 일은 [작업 방식](https://johyunbin.github.io/ozl/how-it-works/)에 있습니다.

## 자동으로 하는 일과 직접 하는 일

| 자동 | 직접 |
|---|---|
| 피드 읽기, 같은 사건 묶기, 다루지 않을 소재 거르기 | 쓸 소재 고르기, 미루기, 버리기 |
| 카드 초안과 검증 기록 초안 | 검증 기록마다 원문과 눈으로 대조 |
| 다른 에이전트의 원문 재확인 | 공개 승인과 철회 |
| 보고서 만들기, 사이트에 올리기 | 슬라이드 마감 |

초안과 재확인에는 언어 모델을 씁니다. 주로 Claude 이고, 해석이 지나치지 않은지는 Gemini 와 ChatGPT 에 한 번 더 읽힙니다. 모델이 "확인했다"고 적은 것은 공개 근거로 치지 않습니다. 검증 기록 파일의 `human_verified_by` 와 `human_verified_at` 에 누가 언제 대조했는지 남고, 사람이 대조하지 않은 주장은 `확인` 배지를 받지 못합니다.

## 숫자를 확인하는 방법

출처를 다섯 등급으로 나눕니다.

| 등급 | 무엇 | 쓰는 법 |
|---|---|---|
| T1 | 공식 통계, 법정 공시, 법령과 판결문, 기관 보도자료 원문 | 단독으로 쓴다. 단위, 기준 시점, 잠정치 여부를 확인한다 |
| T2 | 국제기구, 국책연구기관, 동료 심사를 거친 연구 | 단독으로 쓴다. 조사 방법을 함께 적는다 |
| T3 | 주요 언론의 사실 보도 | 두 곳 이상에서 확인하거나 T1·T2 원문까지 거슬러 올라간다. 같은 통신 기사를 받아쓴 것은 한 곳으로 센다 |
| T4 | 전문가 의견, 증권사 리포트, 심사 전 논문 | 주장이나 추정이라고 밝히고 반대 의견을 함께 적는다 |
| T5 | 커뮤니티, SNS, 출처 없는 글 | 인용하지 않는다. 소재를 찾는 단서로만 쓴다(커뮤니티 반응 자체가 주제일 때만 가려서 싣는다) |

카드에는 배지가 붙습니다. `확인`은 적힌 숫자가 원문과 같고, 단위와 기준 시점과 비교 대상을 점검했으며, 제가 원문과 눈으로 대조했다는 뜻입니다. 카드가 그 숫자로 펼치는 이야기 전체가 옳다는 보증은 아닙니다. 그래서 카드마다 가장 강한 반론과 남는 불확실성을 따로 적습니다. `추정`은 공식 발표 전의 복수 보도, `단독`은 한 곳만 보도한 내용, `루머`는 확인되지 않은 이야기이고, 제가 대조하기 전에는 `검증 대기`입니다. 공개하는 것은 `확인`과 `추정`뿐입니다.

발행한 뒤에 틀린 것을 찾으면 지우지 않고 [정정 기록](https://johyunbin.github.io/ozl/corrections/)에 남깁니다. 규칙 전문은 [검증 방법](https://johyunbin.github.io/ozl/methodology/)에 있습니다.

## 폴더

| 폴더 | 내용 |
|---|---|
| `daily/` | 날짜별 보고서. 승인한 카드만 전문이 들어 있습니다 |
| `claims/` | 공개한 카드의 검증 기록. 주장 하나에 파일 하나입니다 |
| `docs/` | 사이트 문서: 작업 방식, 검증 방법, 쓰는 소스, 정정 기록 |
| `src/ozl/research/` | 수집, 묶기, 카드 검사, 보고서 생성 코드 |
| `src/ozl/analyze/`, `src/ozl/render/` | 슈카월드 슬라이드 구성을 분석하는 코드와, 만들고 있는 슬라이드 초안 생성 코드 |
| `tracks/syuka/` | 슈카월드 방송 자료를 분석한 결과(장수, 구성, 글꼴과 색) |
| `skills/ozl/` | 하루 작업 절차서 |

원본 영상, 전사, 캡처 화면, 승인 전 카드와 초안은 이 저장소에 없습니다.
