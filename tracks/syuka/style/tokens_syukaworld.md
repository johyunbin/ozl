# 슈카월드 슬라이드 스타일 토큰 v1 (2026-11-10)

슈카월드 생방송 슬라이드의 겉모습을 측정으로 복원한 값이다. 근거 집계는 [`../analysis/style_measure_syukaworld.md`](../analysis/style_measure_syukaworld.md)(색·폰트·크기)와 [`../analysis/slide_structure_syukaworld.md`](../analysis/slide_structure_syukaworld.md)(장수·레이아웃), 측정 코드는 `src/ozl/analyze/`, 생성기 반영은 `src/ozl/render/deck.py`.
원본 프레임과 슬라이드 문구는 저작권 때문에 공개하지 않는다. 여기에는 집계 수치만 둔다.

## 크기에 대하여

글자 크기는 한 영상 안에서는 거의 일정하지만(30편 중 27편에서 사분위 범위 ±0.05px 안팎) 영상끼리는 31.7~35.3px 로 다르다. 같은 날 방송에서 나온 클립은 값이 같고, 줄 간격 ÷ 글자 크기는 전부 1.80 이다. 따라서 서식은 하나이고 **방송 회차마다 송출 배율이 다른 것**으로 본다(전체 프레임 3장에서 캔버스 크기도 1190×682 · 1213×704 · 1219×687 로 달랐다). 원본 파일의 pt 값은 영상만으로 확정할 수 없다. 26pt 는 화면에 보이는 크기의 중앙값이다.

## 검증

같은 문구를 이 토큰으로 조판해 파워포인트로 렌더한 뒤 원본 프레임 한 장(글자 크기가 중앙값과 같은 회차)과 겹쳤다. 제목 1줄·본문 7줄 모두 위치 오차 ±1px, 줄 폭 오차 평균 −0.7%, 줄 간격은 원본과 렌더가 59.6px 로 같았다.

측정 코드는 독립 검증 두 번을 거쳤다. 다른 영상에서 줄을 새로 골라 폰트·색 결론을 재현했고(폰트 9줄 중 7줄 일치), 코드 리뷰에서 나온 계산 결함 12건을 고친 뒤 다시 집계했다.

## 측정에서 배운 것

- 추출 프레임의 36%는 화면 필기 도구의 저장 확인 대화상자가 뜬 장면이었다. 걸러내지 않으면 제목색이 연분홍으로, 본문색이 회색으로 잡힌다.
- 2px 굵기의 가는 글자는 영상 압축으로 색이 어둡게 번진다. 색은 굵은 획의 안쪽 픽셀에서 재야 한다.
- 글자 높이로는 폰트 크기를 못 정한다(줄마다 ±3%). 같은 문장을 후보 폰트로 렌더해 **폭**을 맞추면 한 영상의 수십 줄이 0.3% 안에 모인다.
- 파워포인트의 배수 줄 간격은 글자 크기의 1.2배가 기준이다. LibreOffice 는 폰트 줄 높이(맑은 고딕 1.33배)가 기준이라 같은 "1.5줄"도 줄 위치가 달라진다.
- 장면 전환 검출 뒤 비슷한 이미지를 지우는 흔한 추출법은 슬라이드의 44%를 놓쳤다. 배치가 같은 슬라이드가 같은 이미지로 판정되기 때문이다. 장수는 3초 간격 표본과 제목 문장 대조로 다시 셌다.

## 미확정

원본 파일의 글자 크기(화면 겉보기로 25~28pt) · 캡션 크기 · 표·차트 양식 · 연도별 변천. 한 편에서는 본문이 맑은 고딕 Semilight 에 더 가깝게 측정됐다(영상 화질 영향인지 미확인).
