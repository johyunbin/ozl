# 공개, 커밋, 푸시, 백업, 공개 문서 문체

무엇을 공개 저장소에 올리고 무엇을 비공개로 두는지, 어떻게 커밋하고 올리고 백업하는지, 공개 문서를 어떻게 쓰는지의 규칙이다. 핵심은 `CLAUDE.md` 에 있고, 여기는 세부다.

## 공개와 비공개의 경계 (사용자 결정 2026-11-09)
- **공개**: 방법론, 일일 보고서, 클레임 레코드, 사례 연구, 코드, 주제 분포 집계, 스타일 가이드, 템플릿 덱, **사용자 승인된** 제출 PPT. 이슈 기록은 사용자가 승인한 판만 공개용 내보내기로 나간다(공개 게시한 이슈는 아직 없다).
- **비공개(`private/` · gitignore)**: 원본 영상, 오디오, 전사 전문, 추출 프레임, **슬라이드 문구(문자 인식 결과)**, 원시 메타(API 정책), PPT 초안, 계획과 검토 원문, 실제 이슈 기록과 원문 사본, 운영 자료(`private/ops/`, `<자료 루트>/ops/`). 전사 전문과 슬라이드 문구는 어떤 형태로도 외부 공유 금지(집계만). 코드와 테스트의 예시 문장도 지어낸 것만 쓴다.
- 공개 저장소에는 실제 이슈의 내용을 두지 않는다. 예시는 지어낸 것만(`tests/fixtures/issues/`, `apps/web/sample-data/`).

## 공개본 추출 게이트
- 공개 산출물은 **공개본 추출 게이트**(`scripts/publish_gate.py` — 발표자 노트, 숨김 슬라이드 제거, 전사 연속 20자, 슬라이드 문구 연속 15자 인용 차단 · md 뿐 아니라 `src/`, `tests/`, json 도 검사)를 통과한 것만 커밋한다. 검사 대상에는 `apps/web` 의 화면과 예시 자료, 스킬 문서, `README.md` 도 든다. 쓰는 법: `.venv/bin/python scripts/publish_gate.py <파일…>`.
- 게이트를 고치면 양성 반례(비공개 문구 한 줄 삽입)로 발화를 확인한다.

## 커밋과 푸시
- 위임 범위와 `scripts/push_delegated.sh` 규칙은 `CLAUDE.md` 에 있다. 이 스크립트는 위임 범위(`daily/`, `docs/`, `claims/`)만 건드린 커밋을 골라 올리고, 코드 커밋이 로컬에 쌓여 있어도 딸려 보내지 않는다(병합 커밋과 범위가 섞인 커밋은 보류). `--dry-run` 으로 무엇을 올릴지 먼저 본다.
- 코드와 설정 커밋을 사용자가 푸시하라고 말한 뒤 `git push origin main` 으로 올리기 전에: 원격 대비 앞뒤 커밋 수, gitleaks, 공개본 게이트, 테스트.
- `tracks/syuka/decks/` 로 덱을 옮겨 공개하는 것은 사용자가 "올려"라고 한 뒤다(`agent/deck.md`).

## 비공개 기록 백업 (2026-11-10)
- `private/` 는 별도 git 저장소이고 비공개 원격 `ozl-private` 로 올린다. 무엇이 올라가는지는 `private/.gitignore` 의 허용 목록이 정한다: `desk/`(카드와 클레임 정본, 수집 원본, 발급 대장, 이슈 기록, 운영 자료 `desk/ops/` — 원문 사본 `captures/`, `sources/` 는 깊이와 관계없이 뺀다), 전체본과 검증 시트, 계획, 설명서, 조사 문서, 태그 파일, 수집 DB 스냅숏, 열람 문서(md, PDF), 덱 사양과 완성본, 옛 이슈 브리핑 덱. 목록을 바꾸면 이 줄도 고친다. 영상, 전사, 프레임, 원문 사본, 유튜브 통계, 로그인 토큰(`private/ops/`)은 올라가지 않는다.
- 올릴 때는 `scripts/backup_private.sh` 만 쓴다(원격이 비공개인지 확인한 뒤 올린다). 회차가 끝날 때마다 돌린다.
- 원문 사본(`private/desk/captures/`)은 백업 대상이 아니다. 그런데 「원문 일치」 기록은 덱 엄격 검사와 공개 판정(`publishable`)이 쓸 때마다 사본을 다시 해시하므로, 사본이 없는 기기에서는 그 기록을 받지 않고 그 카드도 공개되지 않는다. 「원문 일치」 카드를 공개하기 전에 사본 보관 방법을 정한다. 완성 절차의 진행 기록과 검토 원문(`private/desk/builds/`)은 `desk/` 아래라 백업된다.

## Notion 에 올리는 것
- 소재 카드의 미러는 `agent/desk.md`, 이슈 기록의 행은 `agent/issues.md` 에 있다. 어느 쪽도 본문, 근거 사본, 확인되지 않은 의혹의 내용, 개인 정보를 올리지 않는다.

## 공개 문서 문체 (2026-11-10)
- 한 일을 적고 꾸미는 말을 뺀다. 구호, 이모지, 가운뎃점으로 명사를 길게 잇는 나열, 근거 없는 형용사를 쓰지 않는다.
- 구현된 것만 현재형으로 쓴다. 아직 손으로 하는 일은 손으로 한다고 적는다. 쓰지 않는 도구와 소스는 적지 않는다(`docs/sources.md` 는 `scripts/build_sources.py` 로 만든다 — `agent/ops.md`).
- 규모 숫자(피드 수, 모델 수)를 앞세우지 않는다. 첫 화면에는 결과물 하나와 그 검증 기록을 둔다.
- 자동으로 한 일과 사람이 한 일을 섞어 쓰지 않는다. 모델을 쓴 사실은 숨기지 않는다.
- 승인 전 카드의 제목이나 소재를 공개 문서에 적지 않는다(번호와 분야까지만). 승인 전 이슈 기록도 같다.
- 문서 첫머리의 규칙은 `CLAUDE.md` 둘째 문단에 있다.
- 공개 문서는 `scripts/style_check.py` 로 검사한다(`--quiet-info` 는 알림을 끈다).
