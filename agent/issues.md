# 이슈 기록 만들기

화제가 된 이슈 하나를 두고 떠도는 주장마다 판정과 근거를 붙인 기록을 만드는 일의 규칙이다. 일일 데스크(옛 소재 카드와 클레임)와 따로 돈다. 공통 규칙은 `CLAUDE.md` 에 있다.

## 정본
- 독자에게 설명한 형식, 판정 기준, 검토의 짜임, 게시 가부: `docs/issue-brief.md`. 일이 도는 순서: `docs/how-it-works.md` 의 「이슈 기록의 흐름」.
- 절차: `.claude/skills/ozl/SKILL.md`(`/ozl make [job_id]`, `/ozl status`)와 단계별 지시서 `.claude/skills/ozl/make/`.
- 판정과 문장의 원칙 20가지: `.claude/skills/ozl/make/principles.md`. 쓰기, 재대조와 문장 대조, 고치기가 모두 이 파일을 쓴다.
- 기록의 형식과 판정 규칙의 정본은 코드다: `src/ozl/issues/`(판정과 근거 조건의 조합표는 `rules.py`). 설계 문서는 `private/plan/issues_spec_20261114.md` 3절.
- 명령은 `.venv/bin/python -m ozl.issues --help` 에 있는 것만 쓴다: `new`, `ids`, `capture`, `machine-verify`, `check`, `review add`, `snapshot`, `hash`, `status`, `links`, `export`, `approve`, `withdraw`, `article-check`, `article-new`.
- 지어낸 예시 기록: `tests/fixtures/issues/`.

## 글(읽는 층)
- 독자가 읽는 글은 이슈마다 `<자료 루트>/issues/<이슈 번호>/article.yaml` 한 파일이다. 위의 기록(`issue.yaml`, `evidence/`, `captures/`, `reviews/`)은 뒤쪽 층으로 그대로 두고, 글의 출처(`sources`)는 가능하면 근거 번호(`evidence`)로 잇는다.
- 칸, 검사, 글쓰기 규칙, 갱신 방법의 정본은 글 형식 명세(`private/plan/` 의 `글형식_명세_20261114.md`)다. 코드는 `src/ozl/issues/article.py`.
- 명령: `python -m ozl.issues article-new <slug> --category "…" --title "…" [--date YYYY-MM-DD]`(번호를 받아 폴더, 최소 `issue.yaml`, 빈 글 뼈대를 쓴다), `python -m ozl.issues article-check <이슈 번호>`(오류가 있으면 종료 코드 1, 마지막 줄 "오류 N, 경고 M"). `check` 도 글이 있으면 같은 검사를 함께 한다.
- 글은 승인 지문에 들고 승인한 판의 고정 사본에 함께 남는다. 글을 고치면 승인과 검토가 풀린다. 사이트 자료의 이슈 목록(`index.json`)에는 글이 있는 이슈만 실린다.
- `issue.yaml` 안에 `article` 칸을 쓰지 않는다(읽기가 멈춘다).

## 판정 넷
- 판정은 확인, 일부 맞음, 사실과 다름, 확인 못 함 넷이다. 작은 주장(`parts`)의 판정은 확인, 사실과 다름, 확인 못 함 셋이다. '확인 못 함'은 거짓이라는 뜻이 아니고, 화면에도 그렇게 적는다.
- 보도만으로는 '확인'을 붙이지 않는다. 보도 기사에만 있는 숫자는 판정의 근거가 되지 않는다. 보도 근거에는 주소, 제목, 매체, 읽은 시각, 기사가 밝힌 근거의 종류만 두고 본문 사본을 두지 않는다.
- 공식 원문과 기관 자료는 `capture` 로 받은 사본을 `machine-verify` 가 다시 해시하고 대조해 통과한 것만 근거로 센다.
- 평가와 전망은 판정하지 않고 입장 칸에 둔다.
- 이슈 화면에는 일일 데스크의 '확인' 배지(사람이 원문과 대조한 기록)를 쓰지 않는다. 판정 옆에 근거의 종류를 적는다.

## 검토의 짜임
- 한 판이 게시 대기가 되려면 그 판의 내용 해시를 본 검토가 모두 통과해야 한다: 원문 사본과의 기계 대조(프로그램), 초안을 쓴 모델과 다른 Claude 모델의 문장 대조, 다른 회사의 모델(ChatGPT 또는 Gemini)의 해석 점검.
- 문장 대조를 맡길 때는 `CLAUDE.md` 의 「문장 대조의 기준」을 프롬프트에 그대로 적는다. 서브에이전트는 모델을 지정하지 않으면 초안과 같은 모델로 돈다. 문장 대조는 모델을 지정해 띄운다(검사기도 초안과 같은 모델의 문장 대조는 세지 않는다).
- 재대조 칸은 검토자만 채운다. 작성자는 다른 프로세스나 에이전트를 띄워 재대조를 채우지 않는다.
- 검토 기록은 더하는 때의 내용 해시에 묶인다. 외부 답을 기록하기 전에 이슈를 고치지 않는다(고쳤다면 `snapshot` 으로 남긴 사본의 해시를 `review add --content-hash` 로 준다).
- 검토 원문은 `<자료 루트>/issues/<이슈 번호>/reviews/` 에 파일로 남긴다. 원문 파일이 없는 검토 줄은 세지 않는다.
- 검토 묶음(외부에 보내는 글)에 숨긴 주장의 내용, 내부 번호, 경로, 모델 이름, 사용자 이름을 넣지 않는다. 다 쓴 뒤 다시 읽어 확인한다.
- 다른 계열의 첫 해석 점검은 시험한 이슈마다 고칠 곳을 짚었다. 검토가 한 번에 끝나는 것으로 일정을 잡지 않는다. 외부 창구는 한 번에 하나씩 쓴다.
- 다른 계열 검토는 `mm_request.py --surface chatgpt|gemini` 로 받는다. 실행기가 띄운 세션(`OZL_OPS_RUNNER=1`)은 Codex 와 `multimodel_request` MCP 도구를 쓰지 않는다.

## 게시 가부와 승인
- 사실 판정과 게시 가부(게시 가능, 보류, 공개 제외)는 따로 정한다. 게시 가부는 내용의 게시 가부다. 검토가 덜 끝났다는 뜻으로 '보류'를 쓰지 않는다.
- 다루는 이유가 비어 있으면 게시할 수 없다. 대상이 일반인이거나 공인의 사생활인 항목은 '공개 제외'이고, 그런 대상을 제목으로 삼지 않는다(검사기가 막는다).
- 특정 사람(공인 포함)을 겨눈 범죄나 비위 의혹 주장은 '보류'로 두고 게시는 사용자가 정한다. 기관 문서가 그 의혹을 언급했어도 같다. 회사나 기관을 겨눈 비위 주장은 이미 널리 퍼졌고 판정을 가를 문서가 무엇인지 적을 수 있을 때만 '게시 가능'으로 둔다. 수사기관이나 법원의 확정 문서가 없으면 판정은 '확인 못 함'이고, 요지를 제목과 첫 화면 문장에 쓰지 않는다(세부는 `.claude/skills/ozl/make/principles.md` 7).
- 만들기 단계: 소재 전체가 사람에 관한 의혹, 선거 판세, 사생활인 것은 만들지 않는다(대기열 항목을 멈춤으로 두고 까닭을 적는다).
- 개인을 특정하는 정보는 기록에 쓰지 않는다.
- 수집과 후보 목록 단계: 민감 소재를 거르지 않고 표시만 한다(사용자 결정). 거르는 것은 위의 만들기 단계와 게시 가부에서 한다.
- 승인(`approve`), 내림(`withdraw`), 공개용 내보내기(`export --public`)는 모델이 실행하지 않는다. 사용자가 운영 화면 `/approve` 에서 한다(시험 자료 루트의 지어낸 이슈로 하는 시험만 예외. `CLAUDE.md` 와 같은 문장이다). 승인은 판 번호와 내용 해시를 함께 보내고, 지금 내용과 다르면 거부된다. 내용을 고치면 판 번호가 오르고 다시 승인해야 게시된다. 게시를 내릴 때는 지우지 않고 내림 기록을 더한다.

## 자료가 놓이는 곳
- 실제 이슈 기록, 근거 기록, 원문 사본, 판은 자료 루트 `private/desk/issues/` 에만 둔다(자료 루트는 `OZL_DESK_ROOT`, 없으면 `private/desk`). 공개 저장소에는 지어낸 예시만 둔다.
- 시험은 `OZL_DESK_ROOT=private/test_desk` 처럼 시험 자료 루트로 한다. 대소문자만 다른 경로나 링크로 실제 폴더를 가리키면 운영 명령이 멈춘다.
- 발행 목록(`issues/manifest.json`), 번호 대장, 고정 사본(`issues/*/revisions/`)은 손으로 쓰지 않는다. 명령으로만 바꾼다.
- 이슈 기록을 손으로 고쳤으면 저장한 뒤 다시 읽어 값이 비어 있는 낯선 키가 없는지 본다(검사기도 정해지지 않은 칸을 거부한다).
- 만들 때 읽은 기사 본문 파일(`check --articles`)은 임시 폴더에 두고 검사가 끝나면 지운다. 저장소와 자료 루트에 남기지 않는다.

## 수집한 단서와 출처
- 커뮤니티 글은 단서 전용이다. 근거와 링크로 쓰지 않는다(검사기가 막는다). 커뮤니티 인기글 목록 수집은 2026-11-14 부터 꺼져 있다. 다시 켜더라도 목록의 제목, 링크, 수치만 받고 본문과 댓글은 열지도 받지도 않는다.
- robots.txt 가 AI 수집기를 막거나 약관이 수집을 금지한 사이트는 쓰지 않는다(커뮤니티 출처의 스위치는 `src/ozl/pulse/community.py` 의 SOURCES). 사이트를 열기 전에 그 사이트의 robots.txt 를 먼저 받는다. 수집 허용 여부는 출처 대장 `src/ozl/research/sources_ledger.yaml` 에 적는다.
- 원문은 공식 배포 위치(기관 누리집, 공시 시스템, 법령 사이트)에서 받는다. 다른 곳에 올라온 사본은 공식 원문으로 세지 않는다.

## Notion 행
- `scripts/notion_rows.py [이슈 번호 …]` 가 이슈 기록에서 요약 칸만 뽑고, Notion 에 쓰는 일은 세션이 Notion 커넥터로 한다(DB 「이슈」는 `이슈 번호`로, 「제작물」은 `제작물 번호`로 찾아 있으면 고치고 없으면 만든다). DB 식별자는 `private/notion_issues.json`. `메모` 칸은 사용자의 것이라 쓰지 않는다.
- 올리지 않는 것: 본문(확인된 사실, 주장의 문장, 흐름, 입장), 근거 사본, 공개하지 않는 주장의 내용, 개인 정보. 이슈 전체가 공개 제외면 제목도 올리지 않는다.
