# OZL 웹 화면 설계

이 문서는 `apps/web/` 을 만드는 사람이 묻지 않고 구현할 수 있게 화면, 자료, 색, 부품, 검색, 점검을 정한다. 무엇을 보여 줄지는 서비스 계획(비공개 서비스 계획 4절, 5-5절, 7-3절 "밤 5")이 정했고, 이 문서는 그것을 화면으로 옮긴다. 둘이 어긋나면 계획이 정본이고, 이 문서가 일부러 다르게 정한 것은 맨 끝 "계획과 다르게 정한 것"에 적었다.

사이트가 읽는 자료의 모양은 `python -m ozl.issues export` 의 출력이 정본이다(비공개 설계 문서 11절보다 코드가 앞선다). 2026-11-14 에 `tests/fixtures/issues/` 를 미리보기용으로 내보내 실제 모양을 확인하고 이 문서를 썼다. 이슈 기록 패키지는 아직 고치는 중이라 칸이 바뀔 수 있다. 그래서 사이트는 모든 칸을 "없을 수 있다"고 보고 읽는다(2-4절).

---

## 0. 정해 둔 전제

- 정적 사이트 생성기 Astro 로 만든다. 서버에서 모델을 부르지 않고, 빌드 때 JSON 을 읽어 HTML 을 쓴다.
- 화면 하나는 한 열이다. 휴대폰 폭(390px)을 기준으로 그리고, 넓은 화면에서는 글 폭만 제한해 가운데 둔다. 카드 3열, 옆 칸(사이드바)은 두지 않는다.
- 자바스크립트가 없어도 모든 글과 링크가 보인다. 스크립트는 "짧게 / 전부" 전환, 검색, 카드 넘기기(1-14), 서비스 워커 등록(4-18)에만 쓰고, 앞의 셋은 스크립트 없이도 쓸 만한 대체 모습이 있다(카드는 세로로 이어 둔다).
- 판정은 넷이다: 확인, 일부 맞음, 사실과 다름, 확인 못 함. 조사 자료(`ux_design_refs.md`)의 "근거 없음"을 더한 다섯 가지는 쓰지 않는다. 자료에 다른 값이 오면 "판정 없음"으로 그리고 빌드 경고를 낸다.
- 화면의 모든 글은 사람이 읽는 말로 쓴다. 내부 번호(`i20990101-01`, `claims.c5`, `T1`)는 화면에 내지 않는다. 미리보기의 운영자용 표시도 "공개 기준으로 뺀 주장 2건"처럼 말로 쓴다.

## 1. 주소와 화면

### 1-1. 주소 표

`<기준>` 은 공개용 `/`, 미리보기용 `/preview/` 이다. 모든 안쪽 링크는 `import.meta.env.BASE_URL` 로 만든다(직접 `/` 로 시작하는 문자열을 쓰지 않는다).

| 주소 | 화면 | 만드는 자료 | 계획 |
|---|---|---|---|
| `<기준>` | 첫 화면 | `days/` 가운데 `topics` 가 있는 가장 늦은 날 + `index.json` | 4-2 |
| `<기준>i/<slug>/` | 이슈 화면(최신판) | `issues/<slug>.json` (+ 같은 판의 `issues/<slug>/r/<판>.json` 이 있으면 그 `trend`) | 4-3 |
| `<기준>i/<slug>/r/<판>/` | 고정판 | `issues/<slug>/r/<판>.json` | 4-3, 4-4 |
| `<기준>i/<옛 slug>/` | 옮겨 간 주소 안내 | 본문 JSON 의 `aliases` (합쳐진 이슈의 옛 주소 이름) | 3-1(설계) |
| `<기준>d/<YYYY-MM-DD>/` | 날짜 쪽 | `days/<날짜>.json` | 4-4 |
| `<기준>d/<YYYY-MM>/` | 달 쪽 | `days/` 목록 | 4-4 |
| `<기준>k/` | 키워드 모음 | `keywords.json` | 이 문서가 더함 |
| `<기준>k/<키워드 주소>/` | 키워드 쪽 | `keywords.json` | 4-4 |
| `<기준>corrections/` | 정정 목록 | `corrections.json` | 4-4 |
| `<기준>about/` | 소개(편집 원칙, 판정 기준, 점수 계산법, 자동과 사람) | 화면 틀 안의 고정 글 + `meta.json` | 4-4 |
| `<기준>report/` | 오류 제보와 권리침해 신고 안내 | `meta.report_contact` 또는 환경 변수 | 5-5 |
| `<기준>search/` | 검색 결과 | Pagefind 색인 | 5-5 |
| `<기준>404.html` | 없는 쪽 | — | 이 문서가 더함 |
| `<기준>i/<slug>/cards/` | 넘겨 보는 카드(최신판) | `issues/<slug>.json` | 4-3, 7-2(밤 10) |
| `<기준>i/<slug>/cards/print/` | 카드 그림 전용 화면(미리보기 빌드에만) | 같은 본문 | 7-2(밤 10) |
| `<기준>offline/` | 연결 없음 안내와 이 기기에 저장된 판 | 브라우저 캐시 | 7-2(밤 10) |
| `<기준>manifest.webmanifest`, `<기준>sw.js`, `<기준>offline.json`, `<기준>icons/` | 홈 화면 추가, 서비스 워커, 지금 살아 있는 판 목록, 글자 로고 | `index.json`, `takedowns.json` | 7-2(밤 10) |

주소 규칙:
- `<slug>` 는 자료의 `slug` 를 그대로 쓴다(`^[a-z0-9]+(-[a-z0-9]+){0,7}$`).
- `<판>` 은 정수(`/r/3/`). 판 파일이 없으면 그 주소를 만들지 않는다.
- 날짜 쪽과 달 쪽은 같은 `d/[key]` 경로를 쓴다. `getStaticPaths` 가 `YYYY-MM-DD` 와 `YYYY-MM` 두 꼴을 모두 내고, 쪽 안에서 꼴로 나눈다.
- `<키워드 주소>`: 키워드를 NFC 로 맞추고, 앞뒤 공백을 지우고, 공백 묶음을 `-` 하나로, `/ ? # % \` 와 제어 문자를 지운다. 한글은 그대로 둔다(`k/버스-요금/`). 링크의 `href` 는 `encodeURI` 를 거친다. 서로 다른 키워드가 같은 주소가 되면 한 쪽으로 합치고 두 키워드를 모두 제목 밑에 적는다(빌드 경고 한 줄).
- 옛 slug 쪽은 `<meta http-equiv="refresh" content="0; url=…">` 와 `<link rel="canonical">`, 그리고 "이 기록은 새 주소로 옮겼다" 한 줄과 링크를 둔다. 옛 slug 가 지금 있는 이슈의 slug 와 같으면 만들지 않고 빌드 경고.

### 1-2. 모든 쪽에 공통인 틀

위에서 아래로(휴대폰 폭):
1. "본문으로 건너뛰기" 링크(초점을 받을 때만 보인다).
2. 머리 줄 한 줄: 왼쪽 `OZL`(첫 화면 링크, 글자만 · 로고 그림 없음), 오른쪽 "검색" 링크와 "날짜" 링크(달 쪽). 높이 48px, 아래 구분선.
3. 미리보기용 빌드에서만: 머리 줄 바로 밑 한 줄 "미리보기 · 공개되지 않은 내용이 섞여 있다 · 자료 만든 시각 1월 2일 07:40". 13px, 바탕 `--surface`, 글자 `--preview`. 큰 배너로 만들지 않는다. 그 밑에 그 쪽의 운영 정보 상자(1-12, 있을 때만).
4. 본문(`<main id="main">`). 첫 화면, 이슈 화면, 고정판은 넓은 화면(1100px 이상)에서 본문 열 옆에 옆 단을 둔다(`Base` 의 `wide`. 머리 줄과 바닥도 같은 폭으로 넓힌다).

### 1-3. 첫 화면 `<기준>`

어느 날을 보여 주나: `days/*.json` 가운데 `topics` 가 null 이 아닌 가장 늦은 날. 그날의 `topics` 로 아래를 채운다.

0. **서비스 한 줄**(17px, 600): "그날 화제가 된 일에서 떠도는 주장마다 판정과 근거를 붙여 기록한다." 쪽의 h1 은 화면 읽기용 "OZL 오늘의 이슈 기록".
1. **기준 줄**(13px, `--muted`): "1월 2일 금 · 07:40 갱신 · 출처 4종 기준". 날짜는 그날, 시각은 `topics.line.updated_at`, 종 수는 `topics.line.source_kinds_ok` 의 길이. 검색과 날짜 이동은 머리 줄의 "검색", "날짜" 한 벌만 둔다(이 줄에 다시 두지 않는다). 수집 실패(`source_kinds_failed`)는 독자 화면에 적지 않고 미리보기의 운영 정보 상자(1-12)에만 적는다.
2. **오늘 새로 뜬 것**(h2). `topics.new` 가운데 공개 기록이 있는 이슈만 순서대로, 많아야 4줄.
3. **며칠째 이어지는 것**(h2). `topics.ongoing`, 많아야 6줄.
   - 한 줄(`<ol>`):
     - 1행: 제목(17px, 700). 이슈 화면으로 가는 링크인데, 긴 제목이 파란 밑줄로 여러 줄 이어지지 않게 본문 색에 밑줄 없이 두고 끝에 `--accent` 색 화살표 "→" 를 붙인다(마우스를 올리면 밑줄). 앞에 `예시` 표시(자료가 `example: true` 일 때).
     - 2행: 상태 문장(15px, `--muted`). 자료의 `status_line` 그대로. 없으면 `topic_state`.
     - 3행: 판정 집계(4-1, `VerdictSummary`): "주장 5건의 판정" 머리 + 0건이 아닌 판정만 확인 → 일부 맞음 → 사실과 다름 → 확인 못 함. 가운뎃점 없이 항목 단위로만 줄을 바꾼다. 주장이 0건이면 "판정할 주장 없음, 확인된 사실만".
     - 4행: `hidden_claims` 가 1 이상이면 "이 밖에 다루지 않은 주장 2건"(따로 한 줄).
   - 항목이 `{keyword, state: "정리 전"}` 이거나 `issue_id` 가 `index.json` 에 없으면 독자 화면에 그리지 않는다(빈 항목). 미리보기에서는 운영 정보 상자에 "정리 전이라 목록에서 뺀 화제 n건: 이름…"으로 적는다. 작업 상태(검토 대기, 작성 중)도 줄에 붙이지 않고 같은 상자에 모은다.
   - 점수 숫자와 막대는 여기에 두지 않는다(이슈 화면에만).
4. **다가오는 일**(h2). `topics.upcoming` 의 `{date, what, url}`. 한 줄: "1월 5일 화" + `what`. `url` 이 있으면 `what` 을 링크로(자료에 주소가 없는 일정은 글자로만).
5. **정리 전 화제**(h2). 머리 밑 한 줄(15px, `--muted`): "일어난 일과 그 출처만 적었다. 떠도는 주장의 사실 여부는 아직 정리 전이다."
   - `topics.pre` 의 항목: 1행 키워드(링크 아님, 17px 600), 2행 `desc`, 3행 매체 이름 링크 2~3개.
   - `flags` 가 개인, 사생활, 범죄 의혹, 선거 판세 가운데 하나라도 있는 항목은 미리보기에서도 그리지 않는다. 운영 정보 상자에 "공개에서 빠지는 항목(사생활) 1건"처럼 수와 까닭만 적는다(제목과 출처는 적지 않는다). 공개용 자료에는 이미 빠져서 오지 않고, 오면 빌드를 실패시킨다.
6. **날짜 이동**: "어제 · 그제 · 날짜 고르기"(4-14).
7. 넓은 화면(1100px 이상): 2·3번을 왼쪽 본문 열(40rem), 4·5번을 오른쪽 옆 단(18rem)에 둔다. 화제 추이는 첫 화면에 싣지 않으므로 옆 단에 두지 않는다.

빈 모습:
- `days/` 가 하나도 없거나 모두 `topics` 가 null: 기준 줄 대신 "아직 공개한 화제 목록이 없다." 한 줄, 그 밑에 `index.json` 의 이슈를 최신 판 시각순으로 "OZL 기록" 목록(제목, 판 표시, 판정 집계)으로 둔다. 이슈도 없으면 "아직 공개한 기록이 없다. 판정 기준과 편집 원칙은 소개에서 볼 수 있다." + 소개 링크.
- 구역이 비면 머리는 그대로 두고 밑에 까닭 한 줄을 적는다. 자료에 `empty_note.new` / `empty_note.ongoing` 이 있으면 그 문장, 없으면 기본 문장: 새로 뜬 것 "오늘 새로 정리한 이슈가 없다.", 이어지는 것 "며칠째 이어지는 이슈가 없다.", 다가오는 일 "날짜가 정해진 일정이 없다.", 정리 전 "정리 전 화제가 없다." 빈 줄을 채우려고 다른 항목을 끌어오지 않는다.

### 1-4. 이슈 화면 `<기준>i/<slug>/`

한 장짜리 세로 화면이다. 탭을 두지 않는다. 휴대폰 폭에서 "주장과 판정"이 첫 화면이나 한 번 넘긴 자리에 오게 위에서 아래로 놓는다. 각 구역은 `<section aria-labelledby>` 이고 h2 를 가진다(머리는 h2 없이 묶는다). 미리보기의 작업 상태, 공개 기준으로 뺀 항목, 검사 경고, 승인 전 화제 추이 표시는 본문에 두지 않고 쪽 맨 위 운영 정보 상자(1-12)에 모은다.

1. **머리**
   - 제목 h1(24px, 데스크톱 28px)이 맨 위다. 앞에 `예시` 표시.
   - 그 밑 한 줄: 판 표시(4-9절) "3판 · 1월 3일 07:40" 과, 고정판이 둘 이상이면 "지난 판 보기"(`#revisions`). 같은 줄 오른쪽(좁으면 다음 줄)에 보기 전환(4-12) "짧게 / 전부 / 카드".
   - 정정 한 줄(정정이나 판정 변경이 있을 때만): "정정 1건, 판정 변경 1건. 정정과 판 기록"(`#corrections` 링크). 정정이 있으면 왼쪽 4px `--v-false` 막대와 "정정 n건"을 `--v-false` 굵게(다른 표시와 섞여 보이지 않게). 전과 후의 문장, 까닭은 아래 "정정과 판 기록" 절에 둔다.
   - 판정 집계(4-1 `VerdictSummary`, "주장 5건의 판정"). `hidden_claims` 가 있으면 밑에 "이 밖에 다루지 않은 주장 n건(공개 기준)".
   - "무엇이 새로운가"(`what_new`)와 "왜 중요한가"(`why_matters`): 15px 굵은 머리 밑에 17px 본문. 비면 그리지 않는다.
2. **주장 목차**("주장으로 바로 가기"): 판정표 순서대로 주장마다 판정 표시와 요지, 누르면 판정표의 그 주장(`#claim-<id>`)으로 간다. 넓은 화면에서는 이 자리 대신 옆 단에 둔다.
3. **판정표**(h2 "주장과 판정"): 4-2절. 그 밑에 "다루는 까닭: …"(`reason`). 끝에 "이 밖에 다루지 않은 주장 n건(공개 기준)" 줄(4-3절). 주장이 0건이면 "판정할 주장 없이 확인된 사실만 정리했다." 한 줄.
   - 판정표 밑에 **확인된 사실**(h3, `facts`): 한 줄에 문장과 출처 이름(링크). `type` 이 `해석` 이면 "해석" 꼬리표.
4. **지금까지**(h2): `so_far` 세 줄을 `<ol>` 로. `masked` 가 있으면 그 문장을 밑에.
5. **흐름**, 6. **누가 뭐라고 하나**, 7. **아직 모르는 것**(번지는 곳, 그림 글), 8. **화제 추이** — 4-4 ~ 4-6절. 비면 그리지 않는다.

빈 모습: 이슈 화면은 자료가 있을 때만 만들어진다. 칸이 비면 그 구역을 그리지 않는다(머리, 판정표, 지금까지는 늘 그린다 — 지금까지가 비면 "지금까지 정리한 줄이 없다.").

### 1-5. 고정판 `<기준>i/<slug>/r/<판>/`

이슈 화면과 같은 틀에 그 판의 JSON 을 넣는다. 다른 점:
- 제목 위에 상자 하나(`--surface` 바탕, 1px `--rule-strong` 테두리, 15px): "지난 판이다. 지금은 5판까지 나왔다. 최신판 보기" 와, 이 판 뒤에 정정하거나 판정을 바꾼 것이 있으면 "이 판 뒤에 바뀐 것 n건" 과 그 목록("3판 판정 변경: <주장 요지> 확인 못 함 → 사실과 다름"). 수는 최신판 `corrections` 가운데 `rev` 가 이 판보다 큰 정정·판정 변경이고, 판정 변경의 주장 요지는 최신판 주장의 `history` 에서 같은 판, 같은 전후 판정을 찾아 붙인다. 이 판 자신의 정정은 이 상자에 넣지 않고 제목 밑 정정 한 줄(1-4)에 둔다. 이 판이 최신판이면 "이 판이 지금의 최신판이다." 만.
- 고정판의 판 표시 줄에는 "지난 판 보기"를 두지 않는다.
- 화제 추이는 그 판의 `trend`(승인할 때 고정한 값)만 쓴다. 없으면 구역을 그리지 않는다.
- `<link rel="canonical">` 은 고정판 자신의 주소(덮어쓰지 않는 기록이므로).
- 내린 판(`takedowns.json` 에 `{id, rev}` 가 있는 판): 공개용 내보내기가 파일을 싣지 않으므로 주소가 없다. 판 목록에서도 그 판은 "2판 · 게시를 내림" 글자로만 두고 링크하지 않는다.

### 1-6. 날짜 쪽 `<기준>d/2099-01-02/`

"새로 뜬 것", "이어지는 것"(h3) 밑의 한 줄은 첫 화면과 같은 꼴에 판을 더한다: 제목 링크, "2판 · 2일째 · 새 사실 1건", 판정 집계. 판은 그날 `records` 에서 같은 이슈의 `rev`, 집계는 화제 항목의 값(없으면 `index.json`). `upcoming`, `pre` 도 첫 화면과 같은 꼴로 h3 밑에.

빈 모습: `topics` 가 null 이면 2번 자리에 "이날의 화제 목록은 남아 있지 않다." 그날 기록도 없으면 3번 자리에 "이날 정리한 OZL 기록이 없다." 둘 다 비고 `restored` 도 없으면 날짜 쪽을 만들지 않는다.

### 1-10. 소개 `<기준>about/`

한 쪽에 h2 다섯. 각 h2 에 `id` 를 단다. 글은 화면 틀 안의 고정 글(`src/content/about.md`)이고, 숫자와 기준은 계획 5-2절(점수), 5-4절(판정과 편집 원칙)과 공개 문서 `docs/methodology.md` 에서 옮긴다. 근거 없는 형용사와 구호를 쓰지 않는다.
1. `#principles` **편집 원칙**: 사람이 아니라 주장을 판정한다. 공개 기준(개인, 사생활, 범죄 의혹, 선거 판세는 싣지 않는다). 판을 올리고 지난 판을 지우지 않는다. 정정은 맨 위에 고정한다.
2. `#verdicts` **판정 기준**: 넷을 표로. 열 = 판정 표시(4-1절 부품 그대로), 뜻, 무엇이 있어야 붙이나. '확인 못 함' 줄에 "거짓이라는 뜻이 아니다". 근거의 종류(공식 원문, 기관 자료, 보도) 설명.
3. `#score` **화제 점수 계산법**: 쓰는 출처 종류, 계산 식의 말 풀이, "화제 점수는 관심의 크기이고, 사실인지나 중요한지를 뜻하지 않는다". 식의 판 번호는 자료의 `trend.formula_version` 과 맞춘다(쪽에 "계산법 1판"). 화제 엔진(대기열 "밤 9")이 아직이면 이 절에는 "계산법은 화제 엔진 1판과 함께 적는다." 한 줄만 두고, 지어낸 식을 쓰지 않는다.
4. `#auto-human` **자동이 하는 일과 사람이 하는 일**: 두 열 표. 자동: 수집, 묶기, 점수, 조사와 판정 초안, 원문 대조, 검사. 사람: 고르기, 게시 승인. 어느 단계에 모델을 쓰는지 숨기지 않는다.
5. `#ai` **AI 사용 고지**: 이슈 화면의 고지와 같은 문장 + 한계("고지가 내용의 정확성을 보증하지는 않는다").

### 1-14. 넘겨 보는 카드 `<기준>i/<slug>/cards/` 와 카드 그림

이슈 화면(최신판)과 같은 본문으로 세로 4:5 카드를 만든다. 고정판에는 카드를 만들지 않는다.

- 장의 차례: 표지(제목, 날짜와 판, 판정 넷의 집계 — 0건도 적는다, "이 밖에 다루지 않은 주장 n건(공개 기준)") → "이번 판"(무엇이 새로운가, 왜 중요한가, `masked` 문장) → 주장마다 한 장(판정표와 같은 순서: 사실과 다름 → 일부 맞음 → 확인 → 확인 못 함) → "아직 모르는 것"(있을 때) → "출처와 정정"(출처 이름과 호스트, 정정 안내, 이슈 화면 링크, 판 번호와 고정 주소).
- 주장 장: 주장 종류 꼬리표와 요지, 판정 표시(4-1 그대로, 지난 판정이 있으면 지운 줄 → 지금 판정), "근거: …"(공식 근거 없이 보도만 있으면 "판정에 쓴 공식 근거 없음"), "퍼진 곳: …"(보도가 있을 때), 나눠 본 판정(`parts`), 확인 못 함·일부 맞음이면 판정하지 못한 까닭과 "무엇이 나오면 판정할 수 있나", 근거 출처(기관 이름과 문서 제목). 이슈 화면의 주장 펼침(4-2)과 같은 규칙이다.
- 싣는 것은 자료에 있는 것뿐이다. 공개 기준으로 뺀 주장은 자료에 없으므로 카드에도 없고, 수만 표지에 적는다. 범죄·비위 의혹 주장에 대한 규칙은 내보내기(이슈 기록 패키지)가 걸러 낸 결과를 그대로 그리는 것이고, 카드가 따로 거르거나 덧붙이지 않는다.
- 넘침: 본문 글자를 줄이지 않고 장을 나눈다. 빌드 때 글자 너비(한글 0.95em, 숫자·로마자 0.62em, 띄어쓰기 0.3em)로 덩어리마다 줄 수를 어림해 본문 높이 21em(카드 폭의 22.5분의 1이 1em. 실제 자리는 21.7em 이고 어림이 실제보다 작게 나오는 몫을 남긴다)을 넘으면 다음 장 "<머리> (이어서)" 로 넘긴다(`src/lib/cards.ts`). 장 끝에 머리 글만 남지 않게, 작은 주장의 범위가 다음 장으로 가면 그 작은 주장도 함께 옮긴다.
- 긴 글 잇기: 자료에서 온 글(확인한 범위, 근거가 말하는 것, 판정하지 못한 까닭, 아직 모르는 것, 본문 문단)이 한 장의 절반보다 길고 지금 장에 다 들지 않으면, 문장 사이(`sentences` 규칙: 따옴표와 괄호 안에서는 가르지 않는다)에서 갈라 지금 장의 남은 자리부터 채우고 다음 장에 잇는다. 문장 하나가 한 장보다 길면 낱말 사이에서 가른다. 글자는 바꾸거나 줄이지 않으므로 조각을 차례로 이으면 자료의 글과 같다. 이어지는 범위의 머리는 "확인한 범위(이어서):", 이어지는 목록 문장은 줄표 없이 같은 들여쓰기로 시작한다. `cards.json` 의 글에는 같은 덩어리의 조각에 같은 `chain` 이 붙고, 그림 찍기가 조각을 이어 판 사본의 문장과 대조한다.
- 표지는 나누지 않는다. 제목이 길어 표지가 본문 높이를 넘으면 제목 글자만 1.625, 1.375, 1.25, 1.125 차례로 한 단계씩 줄인다(60자 제목에 판정 넷과 "이 밖에 다루지 않은 주장" 줄까지 한 장에 든다). 0건 판정도 그대로 적는다.
- 화면: 스크립트가 없으면 카드를 세로로 차례로 둔다. 스크립트가 붙으면 카드 띠(`role="region"`, 초점 받음) 안에서만 옆으로 넘긴다(CSS scroll-snap, 쪽 전체에는 가로 스크롤이 없다). 띠 밑에 "이전", "3 / 11"(`aria-live="polite"`), "다음". 좌우 화살표 키로도 넘긴다(입력칸에 초점이 있을 때는 빼고). 넘길 때 움직이는 효과는 없다. 각 장의 머리(h2)에는 화면 읽기용 "3 / 11:" 이 붙는다.
- 이슈 화면의 보기 전환(4-12)에 "카드" 링크가 있고, 카드 화면에서는 "짧게", "전부" 가 이슈 화면으로 가는 링크다(`?view=short|full` 을 view-toggle 이 받아 남기고 주소에서 지운다).
- 그림 전용 화면(`cards/print/`)은 한 장을 1080×1350 CSS 픽셀로 놓고 사이트 머리와 꼬리가 없다. 화면 카드와 같은 부품이라 같은 자리에서 줄을 바꾼다. 미리보기 빌드에만 만든다(공개용 `getStaticPaths` 는 빈 목록). 공개 사이트에 같은 내용의 쪽을 하나 더 두지 않고, 무료 호스팅의 파일 수를 늘리지 않으려는 것이다. 미리보기는 쪽마다 noindex 이고 robots.txt 가 전부 막는다.

## 2. 자료를 읽는 약속

### 2-1. 어디서 읽나

- 빌드 때 환경 변수 `OZL_SITE_DATA` 가 가리키는 폴더를 읽는다. 기본값 `apps/web/sample-data/`(지어낸 예시, 저장소에 둔다).
- 실제 자료는 내보내기로 `private/out/site_data/` 에 만들고(`python -m ozl.issues export --preview|--public --out …`), 그 경로를 `OZL_SITE_DATA` 로 준다. 저장소 안의 다른 곳에 실제 자료를 복사하지 않는다.
- 읽는 코드는 `src/lib/data.ts` 한 곳이다. 쪽 파일은 JSON 을 직접 열지 않는다.

### 2-2. 두 빌드

| | 미리보기용 | 공개용 |
|---|---|---|
| 명령 | `npm run build:preview` | `npm run build:public` |
| 기준 경로 | `/preview/` | `/` |
| 결과 폴더 | `OZL_WEB_OUT`, 없으면 저장소의 `private/out/web_preview/` (스크립트가 `../../private/out/web_preview` 를 절대 경로로 풀어 쓴다) | `OZL_WEB_OUT`, 없으면 `apps/web/dist/` |
| `OZL_BUILD_MODE` | `preview` | `public` |
| 상태 꼬리표, 미리보기 줄, `internal` | 그린다 | 출력하지 않는다 |
| `trend_now` | `trend` 가 없을 때 "작업본 기준, 승인 전 값" 표시와 함께 쓴다 | 쓰지 않는다 |
| `pre` 의 제외 표시 항목 | 꼬리표 달고 그린다 | 오면 빌드 실패 |
| `robots` | `<meta name="robots" content="noindex,nofollow">` 모든 쪽 + `robots.txt` 전부 막음 | 막지 않음 |
| 검색 색인 | 만든다(기준 경로 `/preview/pagefind/`) | 만든다 |

`package.json` 의 스크립트(뜻만 적는다. 구현자가 정확한 줄을 쓴다):
- `build:preview` = `node scripts/guard.mjs preview && OZL_BUILD_MODE=preview astro build && node scripts/pagefind.mjs`
- `build:public` = `node scripts/guard.mjs public && OZL_BUILD_MODE=public astro build && node scripts/pagefind.mjs`
- `astro.config.mjs` 는 `OZL_BUILD_MODE` 로 `base`(`/preview/` 또는 `/`)와 `outDir` 을 정한다. `trailingSlash: "always"`, `build.format: "directory"`.
- `scripts/pagefind.mjs` 는 결과 폴더에 대해 `pagefind --site <out>` 을 부른다(같은 버전의 npm 패키지를 쓴다).

### 2-3. 빌드 전 검사 `scripts/guard.mjs` (종료 코드)

| 검사 | 실패 시 | 코드 |
|---|---|---|
| `OZL_SITE_DATA/meta.json` 이 없거나 `schema` 가 1이 아니다 | "자료 폴더에 meta.json 이 없거나 형식 판이 다르다" | 1 |
| 공개용인데 `meta.mode` 가 `preview` 이고 `meta.test` 가 참이 아니다 | "미리보기용 자료로 공개용 사이트를 만들 수 없다" | 3 |
| 공개용인데 연락처(`OZL_REPORT_CONTACT` 가 있으면 그것, 없으면 `meta.report_contact`)가 비었다 | "신고 연락처가 비어 있어 공개용 빌드를 멈춘다" | 2 |
| 공개용인데 신고 처리 절차 글(`src/content/report-procedure.md`)이 없다 | "신고 처리 절차 글이 없다" | 2 |
| 공개용인데 `meta.test` 가 참이거나 `example: true` 이슈가 있고, 결과 폴더가 `apps/web/dist/` 다 | "시험 자료는 시험 폴더에만 만든다. OZL_WEB_OUT 을 주라" | 3 |
| 미리보기용인데 결과 폴더가 `apps/web/` 안이다 | "미리보기 결과는 저장소 밖(private/out/web_preview)에만 쓴다" | 3 |

- 빌드 안에서 생기는 실패(공개용에 제외 항목이 옴, 판정 값이 넷 밖인데 공개용임)는 `astro build` 가 예외로 멈추고 0이 아닌 코드로 끝난다.
- 시험(8-3절)은 공개용을 `meta.test: true` 인 예시 자료와 `OZL_REPORT_CONTACT=test@example.invalid`, `OZL_WEB_OUT=<임시 폴더>` 로 만들어 코드 0을 보고, 같은 조건에서 연락처만 빼 코드 2를 본다. 공개용 출력 자리(`dist/`)에는 아무것도 남기지 않는다.
- 공개용 결과 폴더는 빌드 시작 때 비운다(지난 빌드의 쪽이 남지 않게). 미리보기 결과 폴더도 같다.

### 2-4. 없는 칸에 죽지 않기

- `data.ts` 는 파일마다 기본값을 채운 객체를 돌려준다: 목록은 `[]`, 문자열은 `""`, 사전은 `{}`, 숫자는 `null`. 쪽 코드는 기본값을 믿고 `?.` 를 쓰지 않아도 되게 한다.
- 모르는 칸은 버린다. 아는 칸의 꼴이 다르면(목록 자리에 문자열) 그 칸을 기본값으로 바꾸고 빌드 경고 한 줄 "issues/x.json: verdicts.groups 가 목록이 아니다"를 낸다. 경고는 빌드 끝에 모아 센다.
- 공개용에서만 실패로 올리는 경고: 판정 값이 넷 밖, 제외 항목, 슬러그 꼴 위반, 날짜 꼴 위반. 나머지는 경고로 둔다.
- 파일이 없으면: `index.json` 없음 → 이슈 0건. `days/` 없음 → 날짜 쪽 0. `keywords.json`, `corrections.json`, `search.json`, `feed.json`, `takedowns.json`, `aliases.json` 없음 → 빈 값.
- 시각 문자열(`2099-01-02T10:00:00+09:00`, `2099-01-02 07:40`, `""`)은 `format.ts` 의 한 함수가 읽어 KST 로 "1월 2일 10:00" 을 만든다. 못 읽으면 빈 문자열(그 자리를 그리지 않는다). 해가 지금 해와 다르면 "2099년 1월 2일".

|---|---|
| `topics.line` (`updated_at`, `source_kinds_ok`, `source_kinds_failed`) | 기준 줄 |
| `topics.new[]`, `topics.ongoing[]` | 두 구역. 항목 `{issue_id, status_line, verdict_summary, hidden_claims}` 또는 `{keyword, state}` |
| `topics.upcoming[]` | 다가오는 일 |
| `topics.pre[]` (`keyword`, `desc`, `links[{outlet,url}]`, `flags`) | 정리 전 화제 |
| `topics.empty_note` | 빈 구역 문장(내보내기가 아직 싣지 않는다 — 없으면 기본 문장) |
| `records[]` | 날짜 쪽 "그날의 OZL 기록" |
| `restored` (`label`, `items[{rank, article, views}]`) | 복원판 |

`keywords.json` → 키워드 쪽 전부. `corrections.json` → 정정 목록. `search.json` → 검색 숨은 칸을 만들 때 `index` 와 함께 읽는다(본문 JSON 으로 대신할 수 있으면 본문을 쓴다). `takedowns.json` → 판 목록의 "게시를 내림". `feed.json` → 지금은 화면에 쓰지 않는다(뒤에 `feed.xml` 을 만들 때 쓴다). `aliases.json`(아직 내보내기에 없음) → 검색 별칭(5-2절).

### 2-6. 화제 추이 값의 출처

계획 4-3절 8은 "그 판을 승인할 때의 값과 기준 시각으로 고정"이다. 최신판 JSON 의 `trend_now` 는 작업본의 지금 값이라 이것과 다르다. 그래서:
1. 고정판 쪽: 그 판 JSON 의 `trend`.
2. 최신판 쪽: 같은 판의 `issues/<slug>/r/<rev>.json` 이 있으면 그 `trend`, 없으면 본문의 `trend`.
3. 그래도 없고 미리보기용이면 `trend_now` 를 쓰고 "작업본 기준, 승인 전 값" 을 덧붙인다.
4. 그래도 없으면(공개용) 구역을 그리지 않는다.

## 3. 색과 서체

### 3-1. 방향

밝은 종이색 바탕, 검은 글씨, 강조색 하나(링크와 초점), 구분선으로 나눈 목록. 판정 넷의 색은 강조색과 따로 두고, 정당 상징색(밝은 빨강, 밝은 파랑, 주황, 노랑)과 멀게 고른다: 짙은 초록, 짙은 황토, 벽돌색, 회색. 강조색은 파랑 대신 짙은 청록(petrol)으로 해 "파랑 대 빨강" 짝이 생기지 않게 한다. 어두운 화면은 밝은 화면을 뒤집지 않고 따로 정한다. 굵은 고딕과 원색은 카드와 덱 출력 전용이고 웹에는 쓰지 않는다.

### 3-3. 판정을 색만으로 가르지 않기

판정 표시는 늘 **모양 + 글자 + 색** 셋을 함께 쓴다. 색을 못 가리는 사람도, 흑백 인쇄에서도 모양과 글자로 가른다.

| 판정 | 모양(16×16 인라인 SVG, `aria-hidden`) | 글자 | 굵기 | 그 밖 |
|---|---|---|---|---|
| 확인 | 꽉 찬 원 ● | 확인 | 600 | — |
| 일부 맞음 | 왼쪽 반이 찬 원 ◐(테두리 2px) | 일부 맞음 | 600 | — |
| 사실과 다름 | 네모 안의 가위표(선 2px) | 사실과 다름 | 600 | — |
| 확인 못 함 | 빈 원 ○(점선 테두리 2px) | 확인 못 함 | 600 | — |

- 넷 모두 같은 틀(모양 + 글자, 같은 굵기와 크기)이다. '사실과 다름'에만 두르던 글자 테두리 상자는 2026-11-14 에 없앴다(혼자 단추처럼 튀었다). 색과 모양으로만 가른다.
- 모양은 글리프가 아니라 SVG 로 그린다(글꼴마다 ● ◐ 의 크기가 달라서). 색은 `currentColor`.
- 화면 읽기 프로그램은 글자만 읽는다("판정: 사실과 다름").
- 정당 색 점검: 네 색 모두 채도를 낮춘 짙은 색이고, 강조색은 청록이다. 8-2절 시험에서 네 색과 주요 정당 상징색 견본(시험 파일 안에 hex 로만 둔다)의 색차(CIEDE2000)가 20 이상인지 잰다. 20 미만이면 그 판정 색을 고친다.

### 3-4. 서체

- 본문과 제목 모두 Pretendard(SIL OFL). npm 패키지 `pretendard` 를 정확한 버전으로 고정해 설치하고, 동적 부분집합 CSS(`dist/web/static/pretendard-dynamic-subset.css`)를 가져온다. 글꼴 파일은 빌드가 사이트 안에 복사한다(CDN 을 쓰지 않는다 — 미리보기 서비스의 콘텐츠 보안 정책과 개인정보 때문에). `font-display: swap` 을 확인하고, 패키지 CSS 가 다르면 덮어쓴다.
- 대체 글꼴 줄: `Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`.
- 굵기는 400, 600, 700 셋만 쓴다.
- 제목 서체는 계획대로 화면을 만든 뒤 고른다. 처음에는 Pretendard 700 이다. 바꿀 때는 `--font-title` 토큰 하나만 바꾼다.
- 숫자: 판정 요약, 점수, 시각에 `font-variant-numeric: tabular-nums`.
- 한글 줄바꿈: 본문 `word-break: keep-all; overflow-wrap: anywhere;` (긴 주소와 영문도 줄을 넘긴다). `text-overflow: ellipsis` 와 `line-clamp` 는 쓰지 않는다(잘림 0 기준).

### 3-5. 글자 크기, 간격, 폭

글자 크기(`rem` 으로 쓰고, 뿌리는 100% = 16px. 본문은 1.0625rem = 17px)

| 토큰 | 휴대폰 | 768px 이상 | 줄 간격 | 쓰는 곳 |
|---|---|---|---|---|

- 자간 0. h1 만 `-0.01em`.
- 입력칸 글자는 17px(16px 이상이라 iOS 가 확대하지 않는다).

간격(4의 배수): `--sp-1` 4px, `--sp-2` 8px, `--sp-3` 12px, `--sp-4` 16px, `--sp-5` 24px, `--sp-6` 32px, `--sp-7` 48px.

## 4. 부품 목록

부품은 `src/components/` 의 Astro 부품 하나씩이다. 입력은 2-5절의 자료 칸이다. 각 부품은 칸이 비면 아무것도 출력하지 않는다(빈 머리만 남지 않게).

### 4-1. 판정 표시 `VerdictMark`
- 입력: `verdict`, `size`(`sm` 15px / `md` 17px), `struck`(지난 판정일 때 참).
- 출력: `<span class="verdict v-false">` 안에 SVG 모양과 글자(3-3절). `struck` 이면 `--muted` 색과 가로줄(`text-decoration: line-through`) — 화면 읽기에는 "지난 판정: 확인 못 함".
- 넷 밖의 값: "판정 없음"(회색 글자, 모양 없음).
- 판정 집계 `VerdictSummary`: 머리 "주장 5건의 판정"(맨 위 주장의 수 기준, 나눠 본 작은 주장은 세지 않는다) 뒤에 0건이 아닌 판정을 "● 확인 1" 꼴로 잇는다. 항목 사이에 가운뎃점을 두지 않고 간격으로 띄워, 좁은 화면에서 항목 단위로만 줄이 바뀐다.

### 4-2. 판정표 `VerdictTable`
- 묶음 순서 고정: 사실과 다름 → 일부 맞음 → 확인 → 확인 못 함. (계획은 "따로 묶는다"만 정했다. 독자가 먼저 알아야 할 '사실과 다름'을 위에 두고, '확인 못 함'은 맨 아래 따로 둔다 — 자료의 `groups` 순서와 상관없이 화면이 이 순서로 다시 놓는다.)
- 묶음 머리(h3): 판정 표시(md) + "2건". '확인 못 함' 묶음 머리 밑에는 자료의 `note`("거짓이라는 뜻이 아니다")를 쓰고, `note` 가 비어도 이 문장을 화면이 넣는다.
- 주장 한 줄(`ClaimRow`, `<details>`):
  - `<summary>`: 1행 주장 종류 꼬리표(13px, `--muted`) + `gist`(17px). 2행 판정 표시(지난 판정이 있으면 지난 것 struck → 지금 것), "근거: " + `evidence_label`(15px, 비었는데 보도가 있으면 "판정에 쓴 공식 근거 없음"). 그 밑 "퍼진 곳: " + `press_label`(15px, 머리는 `--muted`, 있을 때만, 짧게 보기에서는 근거와 같이 접힌다). 3행 "확인한 범위: " + `scope`(15px, 머리는 `--muted`, 있을 때만, 짧게 보기에서도 보인다), "찾아본 범위: " + `searched`(15px, 한 줄 · 넘치면 줄바꿈).
  - 펼침(안쪽 `--surface` 바탕, 1px `--rule-strong` 테두리와 왼쪽 3px 선): 맨 앞에 "근거가 말하는 것"(`basis` 가 있을 때, 그 판정을 받치는 확인된 사실 문장 목록), 일부 맞음이면 "나눠 본 판정" 목록(`parts`, 판정 표시 sm + gist + "핵심" 꼬리표, 작은 주장의 `scope`("확인한 범위: …")와 `basis` 는 그 밑에), 찾지 못한 것, 판정하지 못한 까닭(목록), 무엇이 나오면 판정할 수 있나, 당사자 입장, 근거 문서(출처 목록 부품의 짧은 꼴), 판정 바뀐 기록(`history` — 내보내기가 게시한 판 뒤에 바뀐 것만 싣는다: "2판에서 확인 못 함 → 3판에서 사실과 다름. 까닭: …").
  - 모든 주장을 `<details open>` 으로 연다("전부" 보기가 기본이고 스크립트가 없을 때도 그렇다). "짧게" 보기에서만 '사실과 다름' 밖의 주장을 접는다(4-12). 단추 상태와 펼침이 늘 맞는다.
  - 주장마다 쪽 안 주소 `id="claim-<자료의 id>"`(주장 목차가 가리킨다).
- 판정 집계는 머리(1-4절 1)에 있으므로 판정표 머리에 다시 적지 않는다. 끝 줄은 4-3.
- 스크립트 없이 동작(`<details>` 는 기본으로 키보드와 화면 읽기를 지원).

### 4-3. "이 밖에 다루지 않은 주장 n건" 줄 `HiddenClaimsLine`
- 입력: `n`, `where`(`list` / `table`).
- `n` 이 0이면 출력 없음. 목록 줄에서는 "이 밖에 다루지 않은 주장 2건", 판정표 끝에서는 "이 밖에 다루지 않은 주장 2건(공개 기준)" 과 소개 `#principles` 링크 "공개 기준". 주장의 내용은 적지 않는다.

### 4-4. 흐름 `Flow`
- `<ol class="flow">`, 왼쪽에 세로 줄(2px `--rule-strong`), 줄마다 점(8px 원, 계기는 꽉 찬 점, 나머지는 빈 점 — 모양으로도 가른다).
- 날짜순(오래된 것이 위). 한 줄: 1행 날짜(13px). `event_date` 와 `report_date` 가 다르면 "1월 1일 일어남 · 1월 2일 보도". 2행 `what`(17px). `kind` 가 `계기` 이면 2행을 700 굵게, 앞에 "계기" 꼬리표. `예정` 이면 "예정" 꼬리표. 3행 출처 이름 링크(13px).

- 연결될 때마다(쪽을 열 때, `online` 사건, 서비스 워커가 켜질 때, 연결된 탐색 뒤 60초마다) `offline.json` 을 받는다. 여기에는 지금 있는 이슈의 주소와 최신판 번호, 고정판 번호, 내린 판이 있다(이슈 번호는 싣지 않는다). 목록에 없는 이슈의 저장분, 목록에 없거나 내린 고정판, 최신판 번호가 바뀐 최신판·카드의 저장분을 지운다. 연결된 채 연 쪽이 404 면 그 저장분도 지운다.
- 캐시 이름에 빌드 식별자(자료 폴더 JSON 전체의 해시 앞 12자, `OZL_BUILD_ID` 로 바꿀 수 있다)를 넣는다. 자료가 바뀐 빌드가 오면 새 서비스 워커가 옛 캐시를 통째로 버린다.

## 5. 검색

### 5-1. 색인 만들기

- 빌드 뒤 `pagefind --site <결과 폴더>` 를 돌린다. 색인은 `<결과 폴더>/pagefind/` 에 생기고, 기준 경로(`/preview/`)를 따라 `<기준>pagefind/pagefind.js` 로 불러온다.
- `<html lang="ko">`.
- 색인 범위: 이슈 최신판 쪽만 `data-pagefind-body` 를 단다. 고정판, 날짜 쪽, 키워드 쪽, 소개, 정정 목록은 달지 않는다(같은 글이 판마다 겹쳐 나오지 않게). 쪽에 `data-pagefind-body` 가 하나라도 있으면 Pagefind 는 그것이 없는 쪽을 색인하지 않는다.
- 색인에 넣는 글: 제목(`data-pagefind-meta="title"`), 지금까지 3줄, 주장 gist, 확인된 사실, 흐름의 `what`. 출처 목록과 바닥은 `data-pagefind-ignore`.
- 걸러 보기 값: `data-pagefind-filter="분야"`(category). 결과 줄에 판, 판정 요약을 쓰려고 `data-pagefind-meta="rev"`, `data-pagefind-meta="summary"`.

### 5-2. 조사 붙은 말과 별칭

Pagefind 는 한국어 형태소를 나누지 않고 띄어쓰기로만 낱말을 가른다. 찾는 말의 앞부분 맞추기는 한다(그래서 "한빛시" 로 본문의 "한빛시가" 가 찾아진다). 거꾸로 찾는 말에 조사가 붙거나("한빛시가"), 띄어쓰기가 다르거나("버스요금"), 다른 이름("리콜")이면 못 찾는다. 그래서 둘을 함께 한다:

1. **숨은 색인 칸**(이슈 최신판 쪽, `data-pagefind-body` 안): `<div class="index-only" aria-hidden="true">` 에 다음을 공백으로 이어 넣는다.
   - `keywords` 전부, 그리고 각 키워드의 띄어쓰기를 뺀 꼴("버스 요금" → "버스요금").
   - 별칭: `aliases.json`(`{"제품 회수": ["리콜", "회수 명령"]}`)에서 이 이슈의 키워드에 걸린 것. 이 파일은 아직 내보내기에 없다(화제 엔진의 별칭 사전이 생기면 내보내기가 싣는다). 없으면 건너뛴다.
   - 어근: 제목과 지금까지 3줄을 띄어쓰기로 나눈 낱말마다 끝의 조사(긴 것부터: `에서는, 으로는, 에게서, 에서, 으로, 에게, 까지, 부터, 처럼, 보다, 이나, 이다, 은, 는, 이, 가, 을, 를, 의, 에, 로, 와, 과, 도, 만`)를 한 번 떼어 남은 말이 2글자 이상이면 넣는다. 숫자+단위("400원", "120억")는 그대로 넣는다.
   - CSS `.index-only` 는 화면 밖으로 빼는 방식(`position:absolute; width:1px; height:1px; overflow:hidden; clip-path: inset(50%)`)을 쓰고, `display:none` 이나 `hidden` 을 쓰지 않는다(Pagefind 가 숨긴 요소를 색인하는지 판마다 다를 수 있어서). `aria-hidden` 으로 화면 읽기에서는 뺀다. 구현 뒤 별칭에만 있는 말("리콜")로 찾아지는지 시험이 확인한다.
2. **찾는 쪽에서 조사 떼기**: 입력을 그대로 찾고, 결과가 0건이면 낱말마다 같은 조사 목록으로 끝을 한 번 떼고, 띄어쓰기를 뺀 꼴과 함께 다시 찾는다. 다시 찾은 결과가 있으면 "'한빛시'로 찾은 결과" 한 줄을 붙인다.

## 6. 접근성과 반응

- 폭 360, 390, 768, 1280px 에서 가로 스크롤 없음(`document.documentElement.scrollWidth <= window.innerWidth`). 표(달력)는 360px 안에 들어가게 칸 크기를 정했고, 다른 표(소개의 판정 기준)는 768px 미만에서 줄마다 쌓는 꼴로 바꾼다. 긴 주소와 영문은 `overflow-wrap: anywhere`.
- 200% 확대와 60자 제목: 잘림 없음. 말줄임, 줄 수 제한, 고정 높이 상자를 쓰지 않는다. 머리 줄은 높이를 고정하지 않고(`min-height` 만) 넘치면 두 줄이 된다.
- 키보드: 모든 링크, 단추, `<summary>`, 입력칸에 Tab 으로 닿는다. 초점 표시는 `:focus-visible { outline: 3px solid var(--accent); outline-offset: 2px; }`, 지우지 않는다. 순서는 화면 순서와 같다(`tabindex` 양수 금지). "본문으로 건너뛰기"가 첫 Tab.
- 화면 읽기: 구역마다 h2, 목록은 `<ol>`/`<ul>`, 판정은 글자, 막대 그림은 `aria-label` 에 수치. 쪽마다 `<title>` 은 "제목 · 3판 · OZL", 날짜 쪽 "1월 2일 기록 · OZL".
- 움직임: 쓰는 효과는 `<details>` 열림과 "짧게/전부" 전환뿐이고 그마저 효과 없이 바로 바뀐다. 링크 색 바뀜에 `transition: color 120ms` 하나를 두고 `@media (prefers-reduced-motion: reduce) { * { transition: none !important; animation: none !important; scroll-behavior: auto !important; } }`. 숫자 올라가기, 등장 효과, 패럴랙스 없음.
- 느린 연결: HTML 에 글이 다 들어 있다(자료를 브라우저에서 받아 그리지 않는다). CSS 는 하나의 작은 파일(인라인 가능하면 Astro 가 인라인), 글꼴은 `font-display: swap`(대체 글꼴로 먼저 그린다), 스크립트는 `type="module"`(지연 실행)이고 검색 쪽과 전환 단추에만 있다. 그림 없음(있게 되면 `width`/`height` 와 `loading="lazy"`).
- 화면 크기에 따라 바뀌는 것은 좌우 여백, h1/h2 크기 둘뿐이다(768px 경계 하나).

### 6-1. 스크립트와 주소의 안전

운영 서버가 미리보기를 운영 화면과 같은 출처에서 내준다. 미리보기 쪽에 스크립트가 끼어들면 운영 화면까지 닿으므로 아래를 지킨다.
- 실행되는 인라인 스크립트를 두지 않는다. Astro 의 작은 스크립트 인라인을 끈다(`astro.config.mjs` 의 `vite.build.assetsInlineLimit: 0`). 글꼴 목록을 늦게 붙이던 `onload=` 속성은 외부 파일 `src/scripts/fonts.ts` 로 옮겼다. 실행되지 않는 자료 블록(`type="application/json"`, 카드 그림 전용 화면)은 둔다. 미리보기 전용 CSS 는 인라인 `<style>` 이다(스크립트 아님).
- 빌드 끝의 `scripts/check-html.mjs` 가 모든 HTML 에서 실행되는 인라인 `<script>` 0개, 인라인 이벤트 속성(`on…=`) 0개, `javascript:` 주소 0개를, 공개용이면 쪽마다 콘텐츠 보안 정책 meta 1개를 본다. 어기면 `build:preview`, `build:public` 이 실패한다.
- 공개용 빌드는 쪽마다 `<meta http-equiv="Content-Security-Policy">` 를 넣는다: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'`. `wasm-unsafe-eval` 은 검색 색인(Pagefind)의 WebAssembly 때문이고, `style-src 'unsafe-inline'` 은 Astro 의 인라인 CSS 와 화제 추이 막대의 `style` 높이 때문이며, `form-action 'self'` 는 스크립트가 꺼졌을 때 검색 상자를 제출하려는 것이다(`'none'` 이면 막힌다). 미리보기 빌드에는 meta 를 넣지 않는다(서버가 응답 머리로 준다).
- 자료에서 온 주소(출처, 흐름과 입장의 출처, 번지는 곳, 다가오는 일, 정리 전 화제의 매체 링크)는 `http://`, `https://` 로 시작할 때만 `href` 에 넣는다(`data.ts` 의 `safeHref`. 읽을 때 한 번 거르고, 쪽에서 다시 거른다). 아니면 링크 없이 글자로만.
- 검색 결과는 `innerHTML` 을 쓰지 않고 DOM 으로 만든다(`src/scripts/search.ts`). 발췌에서는 `<mark>` 만 표시로 남기고 나머지는 모두 글자로 둔다. 결과 주소는 같은 사이트의 기준 경로 안일 때만 링크로 쓴다.

폭 360, 390, 768, 1280(높이 800). 전체 쪽 스크린샷 24장을 `private/out/screens/<YYYYMMDD_HHMMSS>/<화면>_<폭>.png` 에 남긴다. 밝은 화면 24장이 기준이고, 어두운 화면(`colorScheme: "dark"`)은 같은 24장을 `_dark` 로 더 찍는다.

각 화면·폭에서 잰다:
1. **가로 스크롤**: `document.documentElement.scrollWidth <= window.innerWidth` 가 참.
2. **대비**: 화면의 모든 글자 요소(글자 노드를 가진 보이는 요소)에 대해 글자색과, 조상을 거슬러 처음 만나는 불투명 바탕색으로 대비를 계산한다. 24px 이상 또는 18.66px 이상 700 은 3:1, 나머지는 4.5:1 이상. 밝은 화면과 어두운 화면 둘 다. 어긴 요소의 선택자와 값을 적는다.
3. **키보드**: Tab 을 최대 300번 눌러 초점이 간 요소를 모은다. 화면의 보이는 `a[href]`, `button`, `summary`, `input` 이 모두 모음 안에 있어야 하고, 초점이 간 요소마다 `outline-style` 이 `none` 이 아니어야 한다.
4. **확대**: (가) 글자 200% — `document.documentElement.style.fontSize = "200%"` 뒤 390, 1280 에서 다시 1번을 재고, 글자를 가진 요소 가운데 `overflow` 가 `visible` 이 아니고 `scrollWidth > clientWidth + 1` 이나 `scrollHeight > clientHeight + 1` 인 것이 없어야 한다. (나) 쪽 200% — 1280 의 절반인 640 폭으로 같은 검사.
5. **60자 제목**: 첫 화면과 이슈 화면에서 `garam-reservoir-levee` 제목 요소의 글자가 자료의 제목과 같고(잘림 없음), 4번의 잘림 검사를 통과.
6. **느린 연결**: 390 폭, CDP `Network.emulateNetworkConditions`(내려받기 400kbps, 올리기 400kbps, 지연 400ms) 와 캐시 끔. 쪽을 열고 h1 글자가 보이는 시각(`page.waitForFunction` 으로 h1 의 `getBoundingClientRect().height > 0` 이고 글자가 있음)을 잰다. 3초 안이어야 한다. 첫 화면과 이슈 화면 둘.
7. **움직임 줄이기**: `reducedMotion: "reduce"` 로 열고 모든 요소의 계산된 `transition-duration` 과 `animation-duration` 이 0s.

## 계획과 다르게 정한 것

1. **`예시` 표시는 공개용에서도 그린다.** 작업 지시는 "상태 표시(게시 대기, 검토 대기, 예시)는 공개용에 붙이지 않는다"였다. 그런데 `예시`는 작업 상태가 아니라 "지어낸 내용"이라는 내용의 성격이고, 계획 "밤 5"가 "지어낸 자료에는 '예시' 표시"를 요구한다. 공개용 시험 빌드(예시 자료로 만든다)에서 이 표시가 빠지면 지어낸 내용이 실제처럼 읽힌다. 실제 공개용 빌드는 `example: true` 이슈를 `dist/` 에 쓰지 못하게 막으므로(2-3절) 실제 공개 사이트에는 이 표시가 나오지 않는다.
2. **주소를 셋 더했다**: `k/`(키워드 모음), `report/`(신고 안내 — 작업 지시에 화면은 있고 계획 4-4 주소 표에는 없었다), `search/`(검색 결과). 그리고 `404.html`, 옛 slug 안내 쪽.
3. **판정표 묶음 순서를 사실과 다름 → 일부 맞음 → 확인 → 확인 못 함으로 정했다.** 계획은 "따로 묶는다"만 정했고 내보내기의 `groups` 는 확인부터 온다. 독자가 먼저 알아야 할 결론을 위에, "거짓이라는 뜻이 아니다"가 붙는 묶음을 맨 아래에 두었다.
4. **최신판의 화제 추이는 `trend_now` 가 아니라 같은 판 고정본의 `trend` 를 쓴다(2-6절).** 내보내기 설계(11-1)는 최신판 JSON 에 작업본의 `trend_now` 를 붙이지만, 계획 4-3절 8은 "승인할 때의 값으로 고정"이다. `trend_now` 는 미리보기에서만 "승인 전 값" 표시와 함께 쓴다.
5. **강조색을 파랑이 아니라 짙은 청록으로 했다.** 조사 자료 A안은 `#1D4E89`(파랑)였다. 판정 '사실과 다름'의 붉은 계열과 짝을 이루면 두 큰 정당의 상징색처럼 읽힐 수 있어서 바꿨다. 판정 색도 A안보다 채도를 낮춘 벽돌색, 황토색으로 골랐다.
6. **조사 자료의 재방문 띠, "달라진 것만" 보기, 분야 칩, 탭 다섯은 넣지 않았다.** 계획 4-3절이 한 장 화면과 "모든 독자에게 같은 내용"을 정했다.
7. **날짜 쪽 위 덩어리(그날의 화제)는 점수순이 아니라 그날 아침 목록의 구역 순서(새로 뜬 것, 이어지는 것, 다가오는 일, 정리 전)다.** 계획 4-4 는 "점수순"이다. 내보내기의 `topics` 가 구역마다 이미 순서를 정해 주고(새로 뜬 것은 오늘 크기순, 이어지는 것은 점수순 — 계획 5-2), 첫 화면과 같은 모양이어야 그날 첫 화면을 다시 볼 수 있어서다. 날짜 쪽에는 점수 숫자를 싣지 않는다.
8. **"짧게 / 전부" 전환은 맨 위가 아니라 제목과 판 표시 줄 오른쪽에 둔다.** 계획 4-3 은 "맨 위"다. 폭 390 에서 전환 단추, 미리보기 상태, 정정이 제목 위에 쌓여 제목이 500px 아래로 밀렸다. 정정은 제목 위에 고정하되 두 줄로 줄이고 "자세히"로 정정 기록에 잇는다.
9. **첫 화면의 "OZL 기록"(화제 목록이 없는 날)은 최근 30건만 싣는다.** 1년치 가짜 자료에서 모든 기록을 한 쪽에 실으면 첫 화면이 690KB~2MB 가 됐다. 키워드도 300개를 넘으면 목록 쪽은 머리마다 12개만 싣고 머리별 쪽 `keywords/<번호>/` 로 잇는다.

## 내보내기에 바라는 것(이 설계가 기다리는 칸)

- `days/<날짜>.json` 의 `topics` 에 `empty_note` 가 빠져 있다. 지금은 화면이 기본 문장을 쓴다. 내보내기가 실으면 그 문장을 쓴다.
- `topics.new`/`ongoing` 항목에 `slug`·`title` 이 없어 `index.json` 과 `issue_id` 로 잇는다. `issue_id` 가 공개 목록에 없으면 공개용에서는 그 줄을 빼고(빌드 경고), 미리보기에서는 항목에 `keyword` 가 있을 때만 "정리 전"으로 그린다. 제목을 지어 채우지 않는다.
- 공개용 `index.json` 행에 승인 표식(예: `approved_rev`)이 없다. 그래서 사이트는 쪽마다 승인 여부를 확인할 수 없고, 공개용 판정은 `meta.json` 의 `mode`·`test` 와 `example` 검사(guard.mjs) 하나에 기대고 있다. 표식이 생기면 공개용 빌드에서 표식 없는 행을 거른다.
- 검색 별칭 사전(`aliases.json`)이 아직 없다. 본문의 `aliases` 는 옛 주소 이름이라 검색 별칭이 아니다.
- 판 목록을 알려 주는 칸이 없어 `issues/<slug>/r/` 폴더의 파일을 센다.
- 그림(`figures`)에 그림 파일 경로 칸이 없어 지금은 설명 글만 그린다.

## 구현자가 조심할 것

1. **공개용 빌드에 미리보기 전용 내용이 새지 않게 한다.** `internal`, `publish_state`, `trend_now`, 제외 표시가 붙은 정리 전 항목은 공개용에서 CSS 로 숨기는 것이 아니라 출력하지 않는다. 8-3의 4번 시험이 낱말로 확인한다. 공개용 `dist/` 에는 시험 자료를 쓰지 않는다.
2. **모든 안쪽 주소는 `BASE_URL` 로 만든다.** 미리보기는 `/preview/` 아래에서 열리므로 `/` 로 시작하는 주소를 손으로 쓰면 미리보기에서만 깨진다. Pagefind 의 `pagefind.js` 경로와 한글 키워드 주소(`encodeURI`)도 같다. 링크 검사(8-3의 5)를 두 빌드 모두에 돌린다.
3. **없는 칸에 죽지 않게, 그러나 조용히 넘어가지도 않게 한다.** 이슈 기록 패키지가 고치는 중이라 칸이 바뀐다. 모든 읽기는 `data.ts` 를 거쳐 기본값을 받고, 꼴이 다른 칸은 빌드 경고로 센다. 판정 값이 넷 밖이거나 제외 항목이 공개용에 오면 경고가 아니라 실패다. 빈 값을 숫자나 문장으로 지어 채우지 않는다.
