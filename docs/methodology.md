# 검증 방법

카드와 슬라이드에 쓰는 숫자와 주장을 어떻게 확인하는지 적은 규칙이다. 하루의 흐름과 사람이 맡는 일은 [작업 방식](how-it-works.md)에 있다.

## 1. 출처 신뢰 등급 T1~T5

| 등급 | 정의 | 사용 규칙 | 표기 예 |
|---|---|---|---|
| **T1** | 1차 공식 통계, 법정 공시, 원문(KOSIS, ECOS, DART, KRX, BLS, Fed, 판결문, 법령, 공식 보도자료) | 단독 사용 가능. 잠정치인지, 단위, 기준시점, 계절조정, 개정 여부를 확인 | `출처: 한국은행 ECOS, 2026.3Q 잠정 (십억원, 계절조정)` |
| **T2** | 국제기구, 국책연구기관, 동료 심사를 거친 연구와 이들이 가공한 2차 자료(IMF, OECD, WB, BIS, KDI, NABO, OWID, 여심위 등록 여론조사) | 단독 사용 가능. 전망치와 설문은 조사 방법(표본, 시점, 오차)을 함께 적는다 | `출처: OECD Data Explorer (2025, 38개국)` |
| **T3** | 주요 언론의 사실 보도(연합, Reuters, Bloomberg, FT, WSJ, 지상파, 주요 일간지와 경제지) | 2건 교차(같은 통신사 받아쓰기는 1건) 또는 T1/T2 원문 역추적. 익명 단독은 "보도됨"으로만 | `출처: Reuters 보도 (2026.11.08)` |
| **T4** | 전문가 의견·칼럼·증권사 리포트·프리프린트·원출처 미확인 통계 집계 사이트 | "주장·추정"으로만. 반대 시각·컨센서스 병기 | `출처: OOO증권 추정치 (2026.10)` |
| **T5** | 커뮤니티, SNS, 텔레그램, 나무위키, 구글 이미지 검색 | **인용과 이미지 사용 금지.** 소재 단서로만, 반드시 T1~T3로 역추적. 커뮤니티 반응 자체가 주제일 때만 마스킹 캡처 | 데이터·로고 출처 불가 |

## 2. 클레임 레코드 — 수치와 주장 하나에 파일 하나 (`claims/YYYY-MM-DD/<card_id>-cN.yaml`)

아래 값은 형식을 보이려고 지어낸 예시다.

```yaml
claim_id: 2026-01-02-am-01-c2
card_id: 2026-01-02-am-01
text: "중국 고속철 총연장 5만 km 돌파(2025년 말)"
observed: "50,000 km"          # 원문에 적힌 값 그대로 — 사람이 눈으로 대조할 문자열
source: {url:, tier: T1, publisher:, accessed:, archived: <wayback url>}
cross_check: [{url:, tier: T3, publisher:, same_origin_as_source: false}]
status: pending | verified | credible_estimate | single_source | unverified_rumor
checks:
  unit_ok: true                # 단위·자릿수
  base_period: "2025-12"       # 기준시점
  real_vs_nominal: nominal     # 금액 지표 필수
  seasonally_adjusted: n/a
  methodology_match: true      # 국가·기관 간 비교 시 산식 일치
  revision_status: final       # 잠정/확정·사후 개정
  primary_doc_locator: "연차보고서 p.12 표3"
  recalculated: true           # 원자료에서 재계산
  translation_checked: true
counter:                       # 반증 — 수치가 맞아도 해석이 틀릴 수 있다
  core_claim:
  strongest_counter:
  denominator_check:
  residual_uncertainty:
verifiers: {claude:, subagent:, gemini:, chatgpt:}   # 모델이 본 것 = 보조 신호
human_verified: false          # 사람이 원문 캡처와 육안 대조 — true 전에는 슬라이드 반입 불가
human_verified_at:             # 대조한 시각·사람(true 일 때 필수)
human_verified_by:
links: {video_id:, time_range:, slide_id:}   # 전사·클레임·슬라이드 역추적
revision: 1
```

`pending` 은 "아직 사람 대조 전"이라는 뜻이다. 모델이 원문을 열어 값을 맞춰 본 클레임도 사람이 눈으로 대조하기 전에는 `pending` 에 머문다(`verifiers` 칸에 누가 무엇을 봤는지 적는다). 카드의 배지는 그 카드 클레임 가운데 가장 약한 상태를 따른다.

## 3. `확인`(`verified`)이라고 부르는 조건

1. **원본성** — 원문을 직접 열어 확인하고 캡처나 Wayback 아카이브를 남겼다. T3 기사에 기댄 주장은 서로 독립인 기사 두 건을 연다.
2. **정확성** — 원자료에서 다시 계산한 값, 단위, 기준시점, 개정 상태가 맞다.
3. **해석** — 분모·비교군·인과 과장·명목/실질 혼동이 없다.

`확인`은 "적힌 값이 원문과 같고, 위 세 가지 점검을 통과했으며, 사람이 원문과 눈으로 대조했다"는 뜻이다. ③은 분모, 비교군, 인과 과장, 명목과 실질 혼동 같은 흔한 해석 오류가 없는지 본 것이고, 카드가 그 숫자로 펼치는 이야기 전체가 옳다는 보증은 아니다. 출처 등급(T1~T5)은 자료가 어디서 왔는지를 말할 뿐이고, 등급이 높다고 주장이 참이 되지도 않는다. 그래서 레코드에는 출처 등급, 수치 점검(`checks`), 해석 점검(`counter`), 사람 대조(`human_verified`)를 따로 적는다.

지키지 못한 것: 2026-11-10 첫 회차의 공개 기록 34건은 원문 대조는 마쳤지만 아카이브 주소(`archived`)가 비어 있다. 채워 넣으면 이 문단을 지운다.

세 가지 모두 통과하고 `human_verified: true` 여야 `verified`. 단일 원본만 존재하는 통계·공시는 ①②로 충분하다(독립 2출처 요구 안 함). **독립 출처 2개 요구는 논쟁적 주장·T3 기반 주장에만** 적용하고, T3 2건이 같은 원출처면 1건으로 센다. 기업 보도자료 단독은 "해당 기업의 발표"로만 표기. 서로 다른 모델 2/3 합의는 후보 승격 조건일 뿐 — 모델들은 같은 오보를 함께 믿을 수 있다.

## 4. 배지 4단계

카드와 작업판에는 짧은 이름(확인, 추정, 단독, 루머)으로 적고, 사람이 대조하기 전에는 `검증 대기`로 둔다. 아래 표의 꺾쇠 문구는 보고서와 슬라이드에 붙이는 표기다.

| 분류 | 기준 | 채택 | 배지 |
|---|---|---|---|
| ① 확인된 사실 | T1/T2 원문 또는 독립 T3 2곳 실명 교차 + 3차원 통과 | 핵심 근거 | 없음 또는 `[공식 확인]` |
| ② 유력 추정·복수 보도 | 공식 발표 전, 복수 T3 구체 보도 / T2·T4 합리적 추산 | 조건부(단정 금지) | `[외신 보도 종합]` `[시장 추정치·미확정]` |
| ③ 단독 보도·일방 주장 | 1개 매체 익명 단독 / 당사자 일방 | 주의(반론 병기) | `[OOO 단독 / 반론 대기]` |
| ④ 미확인 루머 | 커뮤니티·텔레그램·X 발, 교차 검증 전무 | 원칙 배제(루머 현상이 뉴스일 때만) | `[주의: 사실 확인 안 된 루머]` + 공식 부인 병치 |

## 5. 이미지·시각물

슬라이드를 만들 때 적용하는 규칙이다.

- 로고, 지도, 인물 사진은 **공식 Newsroom/Press Kit, 기관 CI 가이드, 라이선스 스톡**에서만 가져온다. 구글 이미지나 커뮤니티에서 내려받지 않는다.
- 모든 외부 이미지는 역검색(Google Lens, TinEye)을 하고 400%로 확대해 워터마크, 변형된 지도, 합성 흔적을 살핀다. 밈은 유래를 확인하고, 정치·혐오·고인 비하 맥락이 조금이라도 있으면 버린다.
- 언론 기사 인용 = 헤드라인·리드 수준 캡처만, 매체명·일자·링크 명기·아카이브. 보고서 도표 = 출처·페이지 명기, 재가공 시 "재구성" 표기. X·커뮤니티 캡처 금지(공식 계정 성명문만 예외). 인물 사진은 공식 프로필·보도자료·CC만, 피해자·미성년자 금지. 지도는 동해·독도·국경 표기 확인란.
- 차트는 원자료(T1/T2)에서 자체 생성. 축 생략·기준선 조작 금지, 출처 각주 필수.

## 6. 민감 소재 — 임시 기준 (전수 분석 후 확정)

국내 정당과 선거, 정치인 평가, 사법 리스크 단정은 다루지 않는다. 국내 정책은 통계적 결과, 해외 비교, 시장 메커니즘으로만 다룬다. 젠더·종교·지역 비하와 진행 중인 형사 사건의 피해자는 다루지 않는다. 해외 정치와 지정학, 경제사는 다룬다. 극단 커뮤니티의 시각물은 쓰지 않는다. 슈카월드가 실제로 다뤄 온 주제의 분포를 본 뒤 RED/YELLOW/GREEN 표로 확정한다.

## 7. 소재 카드 필수 항목

① 제목 후보 ② 한 줄 요약(훅) ③ **왜 오늘인가**(트리거 이벤트·날짜) ④ 핵심 데이터 3개 + 출처 티어 ⑤ 검증 배지 ⑥ 기존 커버리지(유사 영상·날짜) ⑦ 민감도 신호등 ⑧ 예상 구성(도입→배경→데이터→반전·비교→정리) ⑨ 반전 포인트·평행 사례·비유 후보·브릿지 멘트 ⑩ 리스크. 속보 요약보다 그 뒤의 구조적 병목, 해외에서만 보이는 틈, 과거의 비슷한 사례를 찾아낸 카드를 위에 둔다.

## 8. 공개 발행·정정

- 공개(Pages)에는 배지 ①②이고 발행 승인된 카드만. `pending`·③④는 비공개 뷰에만.
- 그래서 보고서는 두 벌이다. **전체본**(모든 카드 · 비공개)과 **발행본**(`daily/` · 공개). 발행본은 승인된 카드만 전문을 싣고, 나머지는 카드 번호와 분야, 계기, 상태만 남긴다. 검증이 끝나 승인되면 같은 번호 자리에 전문이 들어간다.
- 발행 승인은 사람이 한다. 순서: 검증 시트에서 클레임마다 원문 표기와 원문을 눈으로 대조 → `human_verified` → 배지가 ①이나 ②로 계산됨 → 발행 승인. 예약 루틴과 모델은 `human_verified` 도 발행 승인도 스스로 올리지 않는다.
- 발행 직전 재확인(링크 생존·수치 재대조). 오류 발견 시 `docs/corrections.md`에 정정·철회 기록 — 원문은 지우지 않고 취소선 + 정정문.
- 전사 전문·추출 프레임·원시 메타는 어떤 형태로도 공개하지 않는다(집계만).

## 9. 모델을 쓰는 범위

카드 초안과 원문 재확인에 언어 모델을 쓴다. 어떤 모델이 무엇을 하는지는 [작업 방식](how-it-works.md)에 적었다. 모델의 출력은 자료이지 판단 근거가 아니다. 모델이 제시한 출처는 원문에 접속해 실제로 있는지 확인한 뒤에만 쓰고, 여러 모델의 답이 같았다는 것을 사람의 대조로 치지 않는다.
